## HeroBanner 主图分类切换硬切：旧图垫底 → 新图就绪淡入
- 日期：2026-08-13
- 问题：用户反馈「首页 banner 图占很大权重，切换分类时图片切换没有任何过渡」。分类切换时 `useLayoutEffect` 重置 `setBgIndices([0])` 单层 → 旧图随旧层**直接卸载**，新 `<img>` 全新挂载（key=item.id）；且新分类图未预加载 → 加载期间 banner 空白 → 图片加载完直接「蹦」出。轮播有「旧层垫底 + is-active 淡入」crossfade，但分类切换绕过了它。
- 旧逻辑：切换帧起单层渲染新首项图（is-active 动画在图片未就绪时已播完，等于无过渡）。
- 新逻辑（渲染期派生 + switchReady 状态机）：
  - 切换帧（items 引用 vs 上一 commit 不同）由**渲染期派生**：旧活跃图快照 → `--stale` 滞留层垫底（DOM 底层 opacity 1）；**新层不渲染**（hideNewLayer）。
  - `useLayoutEffect` 同帧 `setStaleSnapshot`（幂等同值，供过渡期继续垫底）+ `setSwitchReady(false)` + `new Image()` 预加载新首项图（`switchLoadRef` 防快速连点竞态）。
  - 预加载就绪（onload/onerror fail-open）→ `switchReady=true` → 新层挂载即 is-active（图片已缓存 → heroBgFadeIn 0.8s 淡入完整播放）。
  - 清理 effect（switchReady 变化后 1.2s，不依赖动画事件）移除滞留层。
  - ⚠️ 关键设计：过渡期判断 = `itemsChanged || !switchReady`——**渲染期派生只覆盖切换那一帧**，不能依赖 effect setState 时序（首版实现因此踩坑：img 挂载时 bgPending 闭包陈旧 + load 事件早发 → 永远卡透明层；且 useLayoutEffect 的 setState 在「旧 bgIndices + 新 items」渲染之后才应用，存在一帧竞态）。
- 涉及文件：`src/components/HeroBanner/HeroBanner.tsx`（switchReady/switchLoadRef/staleSnapshot state + 渲染期派生 staleLayer/hideNewLayer + useLayoutEffect 预加载分支 + 清理 effect）、`src/components/HeroBanner/HeroBanner.css`（`.hero-banner__bg-layer--stale` 垫底层；`--pending` 类未采用已移除）、`scripts/home.spec.ts`（新增 HOME-061：stale 出现 → is-active 挂载期间 stale 仍垫底 → 淡入完成后移除 → 终态单层）
