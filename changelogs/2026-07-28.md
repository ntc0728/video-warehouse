## 3. Browse：切换直链搜索 tab 跳过重复查询 / 双卡片相连 / 切换筛选触发搜索中（869dbf2）

- 日期：2026-07-28
- 背景：上一提交已还原样式，但 Browse 交互仍有三处不顺手，用户提出改进。
- 改动：
  1. **切换「直链搜索」tab 不再重复查询 CMS**
     - `triggerSearch` 的 cms 分支加守卫：若 `lastCmsSearchedRef.current === q` 直接 return，跳过 `searchCMS`。
     - 利用已有 `lastCmsSearchedRef` 记录上次查询词；smart↔cms 来回切且词不变时不再打 `searchCMS`，仅词真正变化时请求。
  2. **两张卡片相连**
     - `.browse-page` 的 `gap` 由 `var(--space-sm)` 改为 `0`；
     - `.browse-card--search` 去掉底边 border、上圆角；`.browse-card--results` 去掉顶边 border、下圆角；
     - 两者背景/边框一致，合成一张连续大卡片（顶部搜索区 + 底部结果区）。
  3. **切换筛选/排序 tab 触发「搜索中」loading**
     - smart 模式切换筛选/排序时 `useBrowseData` 的 `isRefreshing` 已为 true 但旧数据仍在，原不显示 loading；
     - 在结果区叠加遮罩：`searchMode === 'smart' && isRefreshing && smartHasData` 时渲染 `.browse-refresh-mask`（盖 `AppLoading tip="搜索中…"`）；
     - 条件含 `smartHasData`：初始无数据仍走整页 `AppLoading`，不重复显示；
     - `.browse-results-body` 加 `position: relative` 作为遮罩定位上下文，遮罩 `position:absolute; inset:0` 盖在旧网格上。
- 涉及文件：`src/pages/Browse/index.tsx`（+9）/ `src/pages/Browse/Browse.css`（+28/-6）
- 关联 Demo：无（CSS + 交互改动，dev server 可直接观察）
- 构建：`npm run build` 通过，read_lints 0 错误
