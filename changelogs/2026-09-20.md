## 关键发现

- **守卫必须最先注册**：Playwright 多路由「后注册优先」（types.d.ts:4054），
  守卫 `**/*` 放最前，随后源 mock/TMDB/各测试自建 route 才能盖过它。
- **模式分裂是套件既有属性**：cross-tab 动态 import `/src/*`（dev-only）、骨架契约 B 要生产
  单包 CSS（preview-only）、boot-splash 取证靠 dev 模块 hold。单模式全绿是不可能的，
  e2e-suite 两阶段正是按此切分。
- mock 瞬时返回会抹掉「加载中」形态窗口 → mock 规则统一 600ms 模拟时延（测速 1500ms），
  既保住时序类断言又远快于真实网络。

## 关键结论

- **栏宽两处不同源，勿合并**：home 用定宽 `--home-rail-w`（240/260，无右边框线，
  真实 `.home-two-col` 纯 gap）；browse/收藏/历史/IPTV/设置共用流体 `--rail-w:
  clamp(148px,10vw,248px)`（有右 1px 边框线）。CSS 选择器各持前缀（`.bs-home .bs-rail`
  vs `.bs-split .bs-rail`），裸 `.bs-rail` 会串档。
- **home 栏宽断点是 ≥1920 不是 ≥2560**（Home.css 2K 档 280→260；记忆库同此）。
- **HeroBili 右卡列数以 `useHeroSideCols.ts` 为唯一真源**：2026-09-10 第七轮已
  **删去 1024–1152 的 1 列档**，现行两档（1024–1280→2列 / ≥1281→3列）。
  ⚠️ `HeroBili.tsx` 顶部注释仍写旧三档，是**过期描述**，勿据此改骨架。
- **填充量法**：`.bs-body` 改 `flex:1` 撑满后 `scrollHeight` 恒等容器高（量不到内容高）
  → 改量「host 末子元素底边 − body 顶边」；home/split 的 host 要下钻到
  `.bs-home__main` / `.bs-split__main`（body 末子元素是撑满的包裹层）。
- **截图脚本拦截延迟 10s→3s**：截图走 CDP `Page.captureScreenshot`（无字体等待），
  goto 后 ~300ms 即捕获，3s 足够；10s 会让 29 用例 ×10s /3worker ≈100s 撞
  ad-hoc 档 120s 预算被击杀。

## 第三轮（2026-09-21）：消除 data-shape 读取竞态（测试时序，非产品回归）

shots 首跑 28/29，唯一失败 `/no-such-route→plain` 偶发读成 `home`（同路由 dark 档却过）
→ 定性为**测试时序竞态**：`waitForSelector('#boot-splash',{state:'attached'})` 在静态元素
一被解析即满足，3 worker 并发 + HTML 分块到达时解析器可在「元素入 DOM」与「body 末尾内联
脚本 setAttribute」之间让出，读到 HTML 静态默认 `data-shape="home"`。此竞态 skeleton.spec.ts
2026-09-18 已记录过；但其既定修法 `waitForFunction(readyState!=='loading')` 对截图脚本
**不适用**——那要等被拦延迟的 main.tsx（deferred module）执行完，届时 React 已挂载、
骨架可能已摘除 → 截空。

**修法**：内联脚本末尾（main.tsx 之前）挂 `data-shape-ready` 就绪标记，两个 spec 的同步点
改等 `#boot-splash[data-shape-ready]` —— 精确落在「脚本跑完（data-shape 正确）、React
未摘除」窗口，同时消除竞态与截图截空。改后 21/21 + 29/29 全绿。
