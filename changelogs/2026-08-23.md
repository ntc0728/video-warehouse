## 6. 快速连续切换分类时缩略图/卡片封面闪烁修复

- 日期：2026-08-23
- 问题：首页快速切换分类（点击越快几率越高），右侧缩略图与下方卡片封面切换到新图时有概率闪烁。
- 根因：两处交叉淡入均用「定时器/预加载完成后提交」的在途过渡，再次切分类时未取消，导致多层淡入叠加 + base 滞后于首张（仍显示首张、pending 反复重启）→ 画面抖动。
  - `LazyImage`（卡片封面 crossfadeOnChange）：`handlePendingLoad` 用固定 `setTimeout(CROSSFADE_MS+40)` 提交，快速切换时定时器未清，base（committedSrc）停在首张，pending 反复重启。
  - `HeroThumb`（缩略图）：`new Image()` 预加载 apply 受 `loadingRef` 守卫，但快速切换仍走「旧图垫底 + switching 淡入」多层叠加。
- 新逻辑：
  1. `LazyImage`：新增 `transitionTimerRef`（提交定时器可取消）+ `lastCrossfadeRef`（时间戳）。crossfade effect 检测「距上次变化 <300ms」为快速切换 → 直接 `setCommittedSrc(imageSrc)` + 清 pending，跳过淡入动画，base 立即跟上最新；慢速仍走原 pending 淡入。
  2. `HeroThumb`：新增 `thumbLastChangeRef`，检测「<250ms」快速切换 → 直接落底（`setCurrentSrc` + `setSwitching(false)` + `ready=isImageLoaded`），不垫旧图、不淡入。
- 涉及文件：`src/components/LazyImage/LazyImage.tsx` / `src/components/HeroBanner/HeroBanner.tsx`
- 构建：`pnpm run build` 通过
- 验证：home 45/46 过（HOME-060 预存 flaky）

## 5. HeroBanner 16:9 几何重构（aspect-ratio 驱动）+ 切分类白隙修复

- 日期：2026-08-23
- 问题：① 从首页切到其他分类，banner 与缩略图之间短暂出现白色间隙；② 不规则屏幕 / 手动拖拽视口宽高时，banner、缩略图实际宽高不满足 16:9。
- 旧逻辑：
  - `.hero-banner` 用 `height: clamp(40rem, 28rem+8vw, 56rem)` + `max-height:70vh` 固定高度；缩略图列宽 `calc(var(--hero-banner-h,0px) * 16/27)`，由 JS useLayoutEffect 实测高度注入 `--hero-banner-h`。
  - banner 宽 = 容器宽 − 缩略图列宽，仅当容器宽 = 64H/27 时才 16:9，绝大多数视口下 banner 并非 16:9；JS 注入首帧为 0px fallback，且切分类时高度重算时序导致列宽瞬变 → 白色间隙（卡片浅色底色透出）。
- 新逻辑：
  1. **几何改为纯 CSS aspect-ratio 驱动**：`.hero-banner { aspect-ratio: 64/27 }`（3 张缩略图，N=3 → 16(N+1)/(9N)=64/27；4 张由 JS 内联 style 覆盖 `20/9`），缩略图列宽 `calc(100%/(var(--hero-thumb-count)+1))`。banner=剩余 N/(N+1)，每张缩略图严格 16:9，**任意视口宽度下都成立，且全程无 JS 量高时序**。
  2. **删除 `--hero-banner-h` JS 注入**（`.hero-banner__main` 高度改由 flex + 父级 aspect-ratio 决定），Home.css 骨架同步改为 `aspect-ratio` + 百分比列宽（去掉 `clamp`/`max-height`/`--hero-thumb-count` 在父级声明）。
  3. **白隙修复**：`.hero-banner__main` 加深色调底色 `linear-gradient(135deg, color-mix(primary 18%), color-mix(secondary 12%))`，切分类新层未就绪（透明）时承接深色而非透出卡片浅色；保留 `hideNewLayer = crossfadeSwitch || !switchReady`（!switchReady 是已缓存切换预加载窗口的必要隐藏条件，不可删）。
- 涉及文件：`src/components/HeroBanner/HeroBanner.tsx` / `src/components/HeroBanner/HeroBanner.css` / `src/pages/Home/Home.css`
- 构建：`pnpm run build` 通过
- 验证：home 45/46 过（HOME-060 预存 flaky）

## 4. HeroBanner 圆角重排 + 缩略图切换旧图闪现修复

- 日期：2026-08-23
- 问题：① banner 与缩略图列之间保留 2px 间隙；② 缩略图四角统一 --radius-md，外框圆角不规则；③ 仅激活态缩略图显示标题；④ 首页切到新分类（未缓存）时缩略图先闪旧图 → 骨架 → 新图。
- 旧逻辑：
  - `.hero-banner { gap: 2px }` 造成 banner/缩略图间隙。
  - `.hero-banner__thumb { border-radius: var(--radius-md) }` 四角统一圆角；标题 `.hero-banner__thumb-title` 仅在 `.is-active` 时 `opacity:1`。
  - `HeroThumb` 未缓存分支 `setCurrentSrc(thumbUrl)` 直接改同一 `<img src>`，浏览器在解码新图前保留旧帧，叠加半透明骨架（rgba(0,0,0,0.25)）→ 旧图透出。
- 新逻辑：
  1. `.hero-banner` `gap: 2px → 0`，banner 与缩略图列无缝拼接。
  2. 移除 `.hero-banner__thumb` 统一四角圆角；新增 `@media (width>=1024px)` 块：`.hero-banner__main` 左缘上/下 `border-radius: var(--radius-lg) 0 0 var(--radius-lg)`；列首缩略图右上 + 列尾缩略图右下 `border-radius: var(--radius-lg)`；内侧拼接边保持直角，构成外框圆角。
  3. 同媒体查询内：`.hero-banner__thumb:first-child / :last-child .hero-banner__thumb-title` 强制 `opacity:1`，首/尾缩略图常显标题（3 张布局下即第 1、3 张；4 张布局下列尾即第 4 张）。
  4. `HeroThumb` 主图 `<img>` 加 `key={currentSrc}`：src 变化时强制重建 DOM 节点，消除浏览器保留的旧帧 → 切换新分类只显示骨架→新图，不再闪旧图。
- 涉及文件：`src/components/HeroBanner/HeroBanner.css` / `src/components/HeroBanner/HeroBanner.tsx`

## 1. LazyImage placeholder 加载时不露白（transition:none + solid背景兜底）

- 日期：2026-08-23
- 问题：图片加载时短暂露白色背景，而非持续显示 shimmer 骨架。根因是 `.lazy-image-container.loaded .lazy-image-placeholder` 隐式继承父级 transition，placeholder 先淡出，而 img 的 blur-up fade-in 需 ~0.6s，两者不同步 → 时间窗口内两图均不可见 → 白底。另 `.lazy-image-skeleton` 只有 gradient 无 solid 兜底，浏览器尺寸异常时 gradient 不渲染即露白。
- 旧逻辑：
  - `LazyImage.css` `.lazy-image-container.loaded .lazy-image-placeholder` 仅有 `opacity: 0`，无 `transition:none` → 默认 transition（可能为父元素 0.3s 淡入）延迟 placeholder 消失。
  - `.lazy-image-skeleton` 仅 `background: linear-gradient(...)` 无 solid 底色。
- 新逻辑：
  1. `.loaded .lazy-image-placeholder` 显式加 `transition: none`，placeholder 与 img fade-in 同时消失/出现，消除时间差。
  2. `.lazy-image-skeleton` 加 `background-color: var(--color-placeholder-shimmer-a)` 作为 gradient 失效时的兜底实色。
- 涉及文件：`src/components/LazyImage/LazyImage.css`
- 构建：`pnpm run build` 通过
- 验证：home 45/46 过（HOME-060 预存 flaky，clean master 同 fail，无关）

## 2. 首页卡片封面滚动触发加载 + preload 顺序修复

- 日期：2026-08-23
- 问题：① 所有分类数据一次性加载完后再展示，页面初始化期间所有卡片封面同时加载，首屏体验慢；② `preloadRowCovers` 先标记 w342 缓存再加载 w185，但 w185 还未完成时 w342 缓存标记会误导后续 LazyImage 进入「已加载」态导致跳过实际加载。
- 旧逻辑：
  - `Home/index.tsx` useEffect 中调用 `preloadRowCovers(cat.rows)` 预加载所有行封面（w185+w342）。
  - `preloadRowCovers.ts`：先 `markImageLoaded(cacheKeys)`（w342），再 `img.src=loadUrls`（w185）。但 w342 先标为 loaded，若 w185 还在加载中，LazyImage 会误认为已加载完毕。
  - 所有 TMDBMovieRow 的 LazyImage 立即开始加载（无 scroll 触发）。
- 新逻辑：
  1. `LazyImage.tsx` 新增 `disabled` prop：为 true 时跳过 IntersectionObserver、强制 `isInView=false`，外部组件控制何时允许加载。
  2. `VideoCard.tsx` 新增 `imageDisabled` prop，透传给 LazyImage 的 `disabled`。
  3. `TMDBMovieRow/index.tsx`：对 `.tmdb-movierow-header` 建立 IntersectionObserver（rootMargin 100px，threshold 0），标题进入视口后设 `isHeaderVisible=true`，传入 `imageDisabled={!isHeaderVisible}` 到每张卡；分类切换时（scrollResetToken 变化）重置 `isHeaderVisible=false` 并重建 Observer。
  4. `Home/index.tsx`：移除 useEffect 中的 `preloadRowCovers` 调用，改由滚动触发替代。
  5. `preloadRowCovers.ts`：将 `markImageLoaded(cacheKeys)` 移至 `img.src=loadUrls` **之后**，保证 w185 加载中时 w342 缓存尚未被错误标记。
  6. `Home/index.tsx` 同步将 `.home-skeleton-hero` 外层改为 `.hero-banner__card` 包裹（与其他页面 banner 骨架结构对齐）。
- 涉及文件：`src/components/LazyImage/LazyImage.tsx` / `src/components/VideoCard/VideoCard.tsx` / `src/components/TMDBMovieRow/index.tsx` / `src/pages/Home/index.tsx` / `src/pages/Home/preloadRowCovers.ts`
