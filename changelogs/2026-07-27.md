### 3.2 修正：展开「弹一下」的真正根因是 overflow:clip（3.1 的诊断有偏差）

- 日期：2026-07-27
- 问题：3.1 上线后用户实测，展开仍「弹一下、延迟跟着出来」，且 3.1 的 Demo 与真机对不上。
- 根因修正（推翻 3.1 的"margin-left 瞬时跳导致内容先到位"判断）：
  3.1 的 `transform` 滑入思路本身正确，但当时**同时在 `.app-shell__main` 误加了 `overflow: clip`**
  （本意裁掉滑入的横向溢出）。展开动画起始帧 `.app-shell__scroll` 为 `translateX(-156px)`
  （内容从折叠位 64px 滑入），这 156px 正好**超出 main 左边界(220px)**，被 `overflow:clip`
  整段剪掉 → 内容不是从 64px 连续滑入，而是等 transform 接近 0 才进入 main 视口"突然出现"
  → 即用户看到的"弹一下、延迟跟着出来"。折叠方向因内容向右移被剪不显眼，故只展开侧暴露。
- 新逻辑：
  - **移除 `.app-shell__main` 的 `overflow: clip`**（弹跳元凶）；
  - 横向溢出改由外层 `.app-shell { overflow: hidden }` 兜底裁掉，**不会触发横向滚动条**；
  - `.home-sidebar` 为 `position: fixed` 且 `z-index` 高于主内容，滑入过程中内容始终紧贴
    侧栏右边缘同步移动，无露馅；`StickyHeader` 为 fixed 全宽且无祖先 transform → 无顶栏抖动。
  - 其余（scroll `transform` 滑入 0.24s、AppLayout 的 `sbAnim` 类名触发、reduced-motion 禁用）保留。
- 涉及文件：`src/components/Layout/Layout.css`（仅移除 `overflow: clip` 一行 + 修正注释）
- 关联 Demo：`demos/demo-sidebar-collapse.html` **已重写为结构等价模型**：
  OLD=`.main` 带 `overflow:clip`（真实复现弹跳）/ NEW=去 clip（连续滑入），
  用 fixed 侧栏 + main margin-left + scroll transform 滑入，与真机一致，点「切换」对比展开瞬间。
- 构建：`npm run build` 通过（exit 0）

### 3.3 修正：折叠/收起仍"立即"（动画从未播，触发机制不可靠）

- 日期：2026-07-27
- 问题：3.2 上线后用户实测，折叠/收起是"立即"瞬移、无过渡，明确要"对称、带过渡、不卡顿、非瞬时"。
- 根因（推翻"clip 已修好"的乐观判断）：3.1/3.2 的 transform 滑入依赖 `AppLayout` 的
  `sbAnim` state + `setTimeout(300ms)` 状态机触发 `.app-shell__scroll` 的 `sb-anim-*` 类。
  该机制在 React 批处理下未能可靠地把 animation 类"从无到有"应用到滚动容器，
  导致 `transform` 滑入**从未真正播放**，只剩 `margin-left` 瞬时跳变 → 用户看到的"立即折叠收起"。
  （已用 ref 确认 `CustomScrollbar` 根 div 确实带 `app-shell__scroll` 类、transform 可作用，
  且 `OverlayScrollbar` 为独立浮层不受影响，故非 CSS/组件问题，而是状态机触发失败。）
- 新逻辑：
  - 删除 `sbAnim` state 与 `setTimeout` 状态机；
  - `AppLayout` 新增 `useLayoutEffect`（依赖 `sidebarCollapsed`），直接对
    `scrollContainerRef.current` 执行「移除 `sb-anim-*` → 强制 reflow → 重新 add」重播动画，
    绕过 state 时序；首次挂载跳过以免首屏误播；
  - 滚动容器 className 恢复静态 `app-shell__scroll`，动画由 ref 强制重播驱动。
- 最终效果（用户诉求）：折叠 / 收起 **对称**、**0.24s** 过渡、主内容随侧栏 `width` 同步
  **平滑平移**、靠 GPU transform（不逐帧重排）**流畅不卡顿**、**非瞬时**。
- 涉及文件：`src/components/Layout/AppLayout.tsx`（仅改触发机制；`Layout.css` 的 transform 滑入规则不变）
- 关联 Demo：`demos/demo-sidebar-collapse.html`（OLD 带 clip 弹跳 / NEW 去 clip 顺滑，结构性说明）
- 构建：`npm run build` 通过（exit 0）

### 3.4 重构：用 Grid 接管侧栏偏移，彻底移除 margin-left（按用户方案"Grid + containment"）

- 日期：2026-07-27
- 动机：用户指出 `margin-left` 补偿是反模式，要求"偏移由布局内部处理"。联网核实 Ant Design v6 /
  MUI persistent drawer / AdminLTE 4 均**不用 margin-left**——侧栏是 in-flow 子节点、内容用
  flex:1 / 1fr 自动填满，折叠只动画侧栏宽度。本重构对齐该主流做法。
- 改动：
  - `Layout.css`：`.app-shell` 由 `display:flex` 改为 `display:grid`，默认单列 `1fr`；
    新增 `.app-shell--with-sidebar { grid-template-columns: var(--sidebar-width) 1fr; transition: grid-template-columns 0.24s }`
    与 `.app-shell--sidebar-collapsed` 变体（列宽 `var(--sidebar-width-collapsed)`）。
    折叠/展开**只动画 grid 列宽**，主内容（1fr）由布局自动重新分配，**彻底删除 `margin-left`**。
  - `HomeSidebar.css`：`.home-sidebar` 由 `position:fixed`（脱离文档流）改为 **grid 首列 in-flow 子节点**
    （`align-self:start; margin-top:header-height; height:calc(100dvh-header-height); width:100%`），
    偏移交给 grid 列宽；删除 `position:fixed / width / transition:width` 与 `.home-sidebar--collapsed` 的 width。
  - `AppLayout.tsx`：`.app-shell` 增 `app-shell--with-sidebar`（仅 `!isCompactViewport && !isNative && !isTV`）
    与 `app-shell--sidebar-collapsed` class；`app-shell__main` 退化为纯 grid 项（删 `app-shell__main--sidebar-collapsed`）；
    **删除** 3.3 的 `sb-anim-*` transform 重播 `useLayoutEffect`（动画现由 grid 列宽过渡承担）。
  - 性能兜底：`.app-shell__scroll` 加 `contain: layout`，把折叠时 grid 列宽变化引发的逐帧重排
    局部隔离在滚动容器内，避免逃逸全页（应对首页 HeroBanner + 多行海报网格的重度内容）。
  - 无障碍：`prefers-reduced-motion: reduce` 下 `.app-shell--with-sidebar { transition: none }`，改为瞬时切换。
- 效果（用户诉求）：折叠 / 收起 **对称**、**0.24s** 过渡、**由布局统一处理偏移（无 margin-left）**、
  **不卡顿（contain 隔离重排）**、**非瞬时**。
- 风险与保底：grid 列宽过渡会对重内容逐帧重排（Ant D/MUI 因页面轻所以无感）；本页首页偏重，
  已用 `contain:layout` 缓解。若真机折叠仍掉帧，保底方案是回退为"grid 列宽瞬时跳 + 主内容 transform 滑入"。
- 涉及文件：`Layout.css` / `HomeSidebar.css` / `AppLayout.tsx`
- 构建：`npm run build` 通过（exit 0），`read_lints` 0 错误

- 改动（保底，对齐之前规划）：

### 3.6 真正解法：spacer 占位分离（同时满足「无 margin-left + 流畅 + 侧栏平滑」）

- 日期：2026-07-27
- 背景：3.4（grid 列宽 transition）卡顿；3.5（grid 列宽瞬跳 + transform 滑入）侧栏瞬跳割裂，用户评"效果太差"；
  一度回归 3.3（fixed + margin-left）验证流畅，但带用户讨厌的 margin-left 一行。
- 根因剖析：in-flow 侧栏（grid 首列）折叠只能改 grid 列宽 → transition 逐帧重排卡、瞬跳割裂，
  且 main 必存在偏移声明。fixed 侧栏（脱离流）才能让侧栏平滑（width transition）且 main 宽恒定不重排，
  但需偏移声明（margin-left）——即 3.3 的代价。
- 解法（把「占位」与「可见侧栏」分离，正面满足用户全部诉求）：
  - `HomeSidebar.tsx` 渲染 `<div className="sidebar-spacer">`（app-shell flex 首列 in-flow，
    宽 `var(--sidebar-offset)` 变量、瞬时跳变、仅一次重排）+ `<aside className="home-sidebar">`
    （`position:fixed` 浮层，`width: var(--sidebar-offset)` + `transition: width 0.24s` 平滑收窄）。
  - `Layout.css`：`app-shell` 定义 `--sidebar-offset: var(--sidebar-width)`；
    折叠时 `.app-shell--sidebar-collapsed` 切换为 `var(--sidebar-width-collapsed)`；
    新增 `.sidebar-spacer { flex-shrink:0; width: var(--sidebar-offset) }`（瞬时、无 transition）。
  - `AppLayout.tsx`：`.app-shell` 加 `--sidebar-collapsed` 驱动变量；`.app-shell__main` 退化为纯 `flex:1`、
    **无任何 margin-left**——偏移完全由 spacer 承担，main 不知道侧栏存在。
  - 主内容 transform 滑入（`sb-anim-*`，沿用 3.5 的 `useLayoutEffect` 重播）掩盖 spacer 瞬跳的一次重排，
    与侧栏平滑收窄同步（0.24s）。
- 效果（用户全部诉求）：折叠/收起**对称**、**0.24s 过渡**（侧栏平滑 + 主内容滑入）、
  **无 margin-left**（偏移归布局/spacer 组件内部）、**流畅**（一次重排 + GPU 动画，等同 3.3 体验）、**非瞬时**。
- 改动文件：`Layout.css` / `HomeSidebar.css` / `HomeSidebar.tsx` / `AppLayout.tsx`

## 15. 修复方案 B 展开方向右侧空白跳动

- 日期：2026-07-27
- 问题：展开时 main 用 transform 从 -delta 滑到 0，但 main 实际宽度没变（窄），平移过程中右侧露出 delta 像素空白，动画结束 width 切换后回正 → 视觉跳动。
- 旧逻辑：折叠/展开对称执行（transform 动画 → onfinish 切 width 类），展开方向 main 窄 + 平移 → 右侧空白。
- 新逻辑：展开方向反序执行——
