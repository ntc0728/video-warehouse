# 2026-08-17

## Android 原生 DLNA 投屏模块接入（SSDP 发现 + UPnP AVTransport 推送）

【问题】投屏 UI 与状态机（`CastSheet.tsx` + `castService.ts` 的 `window.CastBridge` 契约）自 8-15 落地后一直是「空态」——Android 端无原生桥注入，`getCastBridge()` 恒 null，`discoverCastDevices()` 恒空数组，用户无法真正投屏到 DLNA 电视/盒子。

【旧逻辑】前端仅预留契约；`android/` 整目录被 gitignore、CI 靠 `cap add android` + `cap sync android` 重建，仓库内没有任何原生 Android 代码，`android/app/src/main/java` 目录不存在（MainActivity 曾在 1a7bf78 被跟踪、17d526d 移除）。

【新逻辑】新增 `scripts/android-dlna-patch/`（原生代码唯一源，与 `android-res-patch/` 同模式），由幂等脚本 `scripts/patch-android-dlna.ps1` 在 cap sync 后复制进 android/：
1. **Capacitor 6 原生插件 `CastBridgePlugin`**（`@CapacitorPlugin(name="CastBridge")` + `@PluginMethod`，注意 Capacitor 6 注解是 `@PluginMethod` 非 `@CapacitorMethod`）：discover/connect/disconnect/setSource/play/pause/seek/setVolume 与前端契约一一对应；网络操作走单线程 Executor，discover 内置 3s 超时（SSDP + 描述拉取共用预算），resolve 不阻塞 UI。
2. **MainActivity**：`registerPlugin(CastBridgePlugin.class)` 必须在 `super.onCreate()` 之前；保留历史 textZoom 反射修复；`WebViewListener.onPageLoaded` 时 `evaluateJavascript` 注入 `window.CastBridge` shim（代理到 `Capacitor.Plugins.CastBridge`，方法内按调用时惰性取插件对象，插件未就绪时 discover resolve 空数组、其余 noop）。
3. **SSDPDiscovery**：MulticastSocket 临时端口绑定 + `setReuseAddress`，优先无线网卡 `setNetworkInterface`（wlan 优先，找不到用第一个 up+IPv4 接口），`WifiManager.MulticastLock` 保组播接收；M-SEARCH 发两次（MediaRenderer:1 + ssdp:all），400ms receive 超时轮询到 deadline；解析 USN→LOCATION 去重（上限 32）；再并行拉 device description XML（XmlPullParser）取 friendlyName + AVTransport/RenderingControl 服务 controlURL（相对地址按 LOCATION base 解析），**必须含 AVTransport 才入设备列表**。
4. **UPnPAVTransport**：SOAP POST + `SOAPAction` 头 + `CurrentURIMetaData`（DIDL-Lite videoItem，URL/标题 XML 转义）；SetAVTransportURI 成功后**自动 Play**（Play 失败仅 warning 不使 setSource 整体失败）；Play/Pause/Stop/Seek(REL_TIME HH:MM:SS)/SetVolume(RenderingControl 0-100)。
5. **AndroidManifest 合并**：追加 `ACCESS_NETWORK_STATE`/`ACCESS_WIFI_STATE`/`CHANGE_WIFI_MULTICAST_STATE` 权限 + `<application android:usesCleartextTraffic="true">`（DLNA 局域网 http 明文），缺失才加、幂等。
6. **接线三条构建路径**：`build-android.ps1`（cap sync + res patch 后调用）、`build-android.bat`（顺带补上了原本缺失的 res patch）、`release-android.yml`（cap sync 后执行）。

【踩坑】
- **PowerShell 5.1 读无 BOM 的 UTF-8 .ps1 会按 GBK 解码**，中文写进字符串字面量直接解析失败（parse error：字符串缺少终止符）。现有 `build-android.ps1` 能跑是因为中文只在注释/Write-Host 里；本脚本字符串里有中文 → 必须给文件加 UTF-8 BOM（node 写回 `\xEF\xBB\xBF` 前缀）。
- **`Copy-Item -Path "$src\*" -Destination $dest -Recurse` 在 PS5.1 会拍平父层级**：`java\com\videowarehouse\app` 被复制成 `java\videowarehouse\app`（丢掉 com）。改为 `Get-ChildItem -LiteralPath $src -Force | ForEach-Object { Copy-Item -LiteralPath $_.FullName -Destination $dest -Recurse -Force }` 逐个复制顶层子项，保结构。
- **权限匹配串重复前缀**：`$perm` 本身已含 `android.permission.`，若匹配串拼成 `"android.permission.$perm"` 会生成 `android.permission.android.permission.ACCESS_NETWORK_STATE` 脏权限 → 直接以 `$perm` 全名匹配。
- **本机 `android/app/src/main/res/` 有一批无效资源目录** `drawable-night-land-hdpi` 等（限定符顺序应为 `land-night-hdpi`，且来源不明、非 res-patch 产物），`mergeDebugResources` 直接 FAILED。CI 由 cap add 重建无此问题，本机调试需手动删除这些目录才能编译。
- `new InetSocketAddress(0, SSDP_PORT)` 构造器不存在，改 `new InetSocketAddress(0)`（临时端口，M-SEARCH 响应是单播回源端口，无需占用 1900）。
