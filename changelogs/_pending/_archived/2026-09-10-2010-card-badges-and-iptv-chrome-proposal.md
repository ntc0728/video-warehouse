## 卡片角标尺寸下调（评分星标 / hero-bili 右栏四角标）

### 已落地改动

**① VideoCard 左上角评分角标（`.video-card-rating`）**

**问题**：胶囊被星标顶高，视觉上「星比数字抢眼、角标偏厚」。

**旧逻辑**：`Icon icon={Star} size="xs"` 走 `--icon-xs = calc(--text-2xs * 1.40)`，
在 1440 是 **14.89px**；而角标文字 `--text-xs` 只有 11.33px。
flex 行高取「最高子项」→ 胶囊高 = 14.89 + 2×1.97 = **18.83px**，而文字自身只有 11.3px 高。

**新逻辑**：在 `.video-card-rating` 内**就地覆写 `--icon-xs: var(--text-xs)`**（星标与角标字号同档）。
必须用 token 覆写而不是直接写 `.video-card-rating svg { width: … }` —— Icon 组件把
`width/height: var(--icon-xs)` 写在 **inline style** 上，样式表规则赢不了 inline；
而 inline 里的 `var()` 是按元素解析的，覆盖 token 就能生效。

实测（各视口角标 宽×高，卡片宽）：

| 视口 | 卡片宽 | 旧 | 新 | 变化 |
| --- | --- | --- | --- | --- |
| 1920 | 166.1 | 43.08 × 19.98 | 38.81 × 15.73 | −10% / −21% |
| 1440 | 138.9 | 41.84 × 18.83 | 38.28 × 15.27 | −9% / −19% |
| 1280 | 152.3 | 41.86 × 18.48 | 38.70 × 15.33 | −8% / −17% |
| 1024 | 134.9 | 41.94 × 17.97 | 39.47 × 15.50 | −6% / −14% |
| 768 | 172.0 | 42.02 × 17.45 | 40.22 × 15.67 | −4% / −10% |
| 375 | 109.0 | 37.66 × 14.59 | 37.06 × 14.00 | −2% / −4% |

**② HeroBili 右栏卡片四角标（`.hero-side-card`）**

**旧逻辑**：四角文字用 `--text-xs`、收藏圆钮用 `--icon-lg`。右栏封面只有 ~100px 高
（16:9 × 178px 宽 @1440），两者相对封面偏重。

**新逻辑**：`.hero-side-card` 内新增两个局部 token，统一收 10%：
`--hero-corner-fs: calc(var(--text-xs) * 0.9)`（四角文字）、
`--hero-corner-fav: calc(var(--icon-lg) * 0.9)`（收藏钮）。

取 0.9 而不是直接降到 `--text-2xs`：后者在 1024 档掉 14%、在 1920 档只掉 1%，
同一「收窄一档」的意图在各视口表现不一致。

实测 1440：文字角标 30.16 → 27.14（宽）、14.72 → 13.25（高）；收藏钮 23.38 → 21.03。

### 移动端 / 小视口角标核查（用户点名）

三个角标的字号与内边距全部走 `--text-xs` / `--space-*` 流体 token，**没有第二套移动端值**，
所以「小视口角标变小」这条实际上**只成立到 token 曲线本身的变化幅度**：
`--text-xs` 在 375 是 12px、768 峰值 12.66px、1440 12.19px、1920 11.09px —— 全程只差 1.6px。

- 评分角标本次改动在 375 只有 −4%（14.59 → 14.00）——因为它已经落在曲线下限，
  星标（12px）与文字（12px）本来就没有落差可收。
- 但**占比**问题与视口无关：375 下卡片只有 109px 宽，一个 37px 的角标占 34%
  （桌面 1440 是 28%）。三个角标在 375 分别占卡片宽 34.0% / 30.6% / 27.5%，
  彼此一致性没问题（都在 27–34%），观感实测正常，**本次未改动移动端**。
- 若后续要「角标随卡片等比缩放」而不是「随视口」，需要把角标字号改成容器查询
  （`.video-card-cover { container-type: inline-size }` + `cqw`），属跨页面视觉改动，未擅自实施。

## IPTV 播放页「频道列表一/二级宽度」+「OSD 栏宽度与内部布局」分析与提案

**本轮只出分析与 Demo，未改动播放器代码**（视觉尺寸类改动需先拍板）。

### 议题一：频道列表一/二级宽度

**问题**：一级（分类）栏太宽、二级（频道）栏太窄。

**现状根因**：`.up-channel-groups` 与 `.up-channel-channels` 的 `width` / `max-width` 都写死 50%
（`UniversalPlayer.css:784-787` / `:885`）。而两级内容性质完全不同 ——
一级是**写死的 10 条固定分类文本**，二级是**自由频道名**。

实测（1440，`--layout-panel-medium-w` = 444.6px）：

| 项 | 数值 |
| --- | --- |
| 一级栏 | 222.3px |
| 一级内容需要（最长名「央视 CCTV」+ 计数药丸 + 内边距，600 字重） | **125.3px** |
| 一级空转 | **97px（44%）** |
| 二级栏 | 222.3px |
| 二级名称可用 | 122.2px |
| 最长频道名 | 157px → **截断 34.9px** |
| 375 下二级名称可用 | **54.5px**（实测被截成「CCTV-5 体育赛事」） |

**建议（方案 A）**：一级改为「内容派生定值」，二级吃剩余。
逐档实测一级需要宽度只有 **118.6 / 125.3 / 125.3 / 125.2 / 125.3 / 129.1px**（375→1920）——
内边距随档变大、字号 768 后反而变小，两者相抵后**与视口宽度没有强相关**，
所以给定值 `--layout-channel-group-w: 132px`（= 上限 +2% 余量），而不是 vw 比例曲线；
≤479 单开一档：组项字号降 `--text-sm`、内边距降 `--space-sm` → 需要宽度 109.6px → 取 116px，
并隐藏质量徽章（375 下频道名可用 54.5 → 128px）。

**关键口径坑（demo 里踩过并已修正）**：不能用 `.up-channel-group-text` 的**渲染宽度**当「内容需要」，
它带 `text-overflow: ellipsis`，栏一窄渲染宽就被裁到可用宽，等于自证「刚好放得下」；
且分类**活跃态是 `font-weight: 600`**，最长的「央视 CCTV」随时可能是活跃项，必须按 600 量。

### 议题二：OSD 栏宽度

**问题**：`--layout-osd-max-width` 在 **约 420–1158px 视口区间恒大于「视口 − 2×--space-md」**，
被 `max-width` 兜底规则吃掉 → 这一段 OSD 实际是**贴边**的，宽度 token 完全不起作用。

实测：

| 视口 | 现状 OSD 宽 | 占视口 | 左右留白 | token 状态 |
| --- | --- | --- | --- | --- |
| 375 | 320 | 85.3% | 27.5px | 生效 |
| 768 | 749 | **97.5%** | 9.5px | 被截断（token 1040） |
| 1024 | 1003.9 | **98.0%** | 10px | 被截断（token 1104.34） |
| 1280 | 1168.7 | 91.3% | 55.7px | 生效 |
| 1440 | 1208.9 | 84.0% | 115.5px | 生效 |
| 1920 | 1342.4 | 69.9% | 288.8px | 生效 |

即「视口越窄、OSD 占比越高」这条反直觉曲线。

**建议**：换成单条比例曲线 `clamp(320px, 78vw, 1400px)` →
375→320（不变）/ 768→599（78%）/ 1024→798.7（78%）/ 1280→998.4（78%）/ 1440→1123.2（78%）/ 1920→1400（72.9%），
全程留白单调、无截断段；TV 档 `clamp(1600px, 83.333vw, 3200px)` 是独立 2× 契约，不动。

### 议题三：OSD 内部布局

**问题**：左翼（`--layout-channel-num-w` 120→180）恒大于右翼（`--layout-quality-badge-min-w` 84→120），
中列的中心不等于 OSD 的中心 → 位于中列的**控件行整体右偏**。

实测 1440：OSD 中心 719.95、控件行中心 747.85 → **右偏 27.9px**（各视口 18–29.5px）。
另右翼堆了三行小字（网络速度 / 线路 / 时间），左翼把频道号单独占一行（高 53.7px）。

**建议 v1（最小改动）**：右翼宽度改用与左翼同一个 token `--layout-channel-num-w`
（≥1024 生效）+ 内容改右对齐 + 三行并两行 + 控件行 `nowrap`（窄屏只留图标）→
实测控件偏移 **27.9 → 0px**（各视口均归零）。

**取舍项 v2**：在 v1 基础上再把频道号并到台名同行（左翼 53.7 → 27.1px，三栏垂直重心更齐），
代价是台名可见宽 130.6 → 101px（长的更早走 marquee）—— 需用户裁决。

### 顺带发现（未修，建议单独立项）

播放器跑在应用默认**浅色主题**下，`--color-primary` = `#000`，而频道列表面板是
`rgba(0,0,0,.60)` 压在视频黑场上 → 所有用 primary 做强调的规则全部退化成黑色、完全不可见：

| 规则 | 实际值 | 效果 |
| --- | --- | --- |
| `.up-channel-group-active::before`（一级活跃左竖条） | `rgb(0,0,0)` | 不可见 |
| `.up-channel-item-active`（二级活跃左边框） | `3px rgb(0,0,0)` | 不可见 |
| `.up-channel-group-active .up-channel-group-count` | `color(srgb 0 0 0 / 0.12)` | 比未选中的 `rgba(255,255,255,.06)` **更暗** |
| `.up-channel-item-active .up-channel-item-num` | `color(srgb 0 0 0 / 0.65)` | 不可见 |

目前唯一生效的活跃线索只有行底色 `rgba(255,255,255,.12)` + 字重加粗。
涉及播放器内约 10 处 `var(--color-primary)` 消费点，建议独立提交 + 逐个回归。
