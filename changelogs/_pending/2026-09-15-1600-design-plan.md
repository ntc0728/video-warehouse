## 三端设计规范实施方案（文字四档 / 字号阶梯 / TV 10-foot 基线 / 移动端）

- 日期：2026-09-15
- 背景：承接同日《三端设计规范审查报告》，用户对报告 §七 三项关键项拍板：① `tertiary` 提档**接受**；② 桌面段2 字号**按行业标准合理设计、不设可读性下限**；③ TV 字号**符合行业主流标准即可**。
- 旧逻辑（被本方案取代的写法）：
  - 报告 §五 提议的「`clamp(下限, 递减曲线, 上限)`」字号下限钳制 → **作废**（用户明确不要下限钳制）。
  - `--color-text-tertiary: #999`（2.85:1）承担信息性文字；`--color-danger` 底 + 白字角标 3.76:1；`.video-card-status--*` 硬编码 Tailwind 色随封面变化低至 2.04:1。
  - 桌面段2 字号逆视口递减（1920 正文 13.00 < 平板 14.00）；2560 处 `--text-xs` = `--text-2xs` = 11.88（塌缩）。
  - TV 1080p 正文 15px / 角标 11px（10-foot 实践下限正文 ≥18sp）；TV rem 曲线实测比文档低 6.25%（根字号 15px ≠ 设计假设 16px）。
  - `--comp-btn-min-height` 移动端 34.66px（HIG 44pt）；`.mobile-tab-bar` 无安全区且 viewport 无 `viewport-fit=cover`。
- 新逻辑（本次产出）：新增 `docs/DESIGN-PLAN-2026-09-15.md`——7 个批次（B0 基线 / B1 色彩 / B2 焦点 / B4 根字号解耦 / B3 字号阶梯 / B5 TV / B6 移动端 / B7 工程化），每批含文件:行号、可直接粘贴的 CSS、实测预期值、验收标准、回归风险与回滚方式。关键设计：
  - **小四档恒定**：`2xs/xs/sm/base` = 11/12/13/14px 全端不流动（仅乘 `--ui-scale`），恒定即消除逆递减、档位塌缩与 rem 循环；移动 390 `--text-2xs` 由 9.05 → 11px。
  - **大四档标准档**：`lg/xl/2xl/3xl` 段2 改为「768 连续 → 1440 命中 16/18/22/28 → 冻结」，全部 `clamp` 斜率 `±0.09926vw` 经公式校验在 768 处精确等于段1 末值。
  - **`--root-font-size` 解耦**（B4 前置）：新增独立 token 复刻现状根字号曲线，`html` 改引用它，使 `--text-base` 调整不再带动全仓 ≈200 处 rem 消费点；实测 8 组视口偏差 0.000%。
  - **状态色双档**：新增 `--color-{success,warning,error,info}-text`（#237804 / #a05c00 / #cf1322 / #0958d9），一个值同时满足「浅底文字」与「白字角标底」；`#ad6800` 实测仅 4.41 已排除。
  - **封面角标统一口径**：`rgba(0,0,0,0.6)` 中性玻璃底 + 白字（任意封面图下最坏 5.74:1），色义改由圆点承载 → 红色只保留「危险 / LIVE」。
  - **TV 10-foot 基线**：1080p 正文 15 → 20px、次要 18、角标 14、标题 30/36，4K 保持 2×；TV 字号块由 rem 改写为 px（TV 根字号被钉 15px，rem 写法会产生第二次「文档值≠实测值」偏差）。
  - **发现的两个既有缺陷**（本方案顺带修复）：`.stylelintrc.json` 存在两个同名 `declaration-property-value-disallowed-list` 键 → 后者覆盖前者，`width/height: 100vw/100vh` 禁令**实际失效**；`index.html` 无 `viewport-fit=cover` 导致 3 处 `env(safe-area-inset-*)` 恒为 0（安全区策略名存实亡）。
- 涉及文件：`docs/DESIGN-PLAN-2026-09-15.md`（新增）、`.gitignore`（新增 `!docs/DESIGN-PLAN-*.md` 与 `!docs/design/` 白名单）。**本轮未改动任何源码**。
