## Demo：CategoryQuickAccess 方案 A2 · 热门分类拓展面板（真实 TMDB 数据，待审阅）

**【诉求】** 在方案 A 基础上拓展：「全部分类」改跳 browse；点击导航 chip 在下方展开面板，显示该分类的 genre 分类 + 该分类最热门搜索值（含热度/搜索值）；默认显示热度最高的分类类型及各自最热门搜索值；数据全部真实 TMDB 接口获取，不写死。

**【demo 实现】**（`changelogs/demos/demo-category-quick-access-a2-2026-09-06.html`，token 与 v2.2 逐字对齐，未动真实源码）：
- **导航条**：首页 / 电影 / 剧集 / 综艺 / 动漫 / 纪录片 / 排行榜 + 「全部分类 →」（点击 → `/browse`，不再 hover 下拉）。各分类 chip 带 🔥 热度徽标（真实 trending 聚合计数）。
- **默认「首页」面板 = 分类热度榜**：`/trending/all/day` 按分类桶（media_type + genre_ids）聚合 Σpopularity 排序——热度最高的分类类型排行 + 每分类最热门搜索值（海报 + 标题 + 🔥popularity + ★评分）+ 热度条；点击行展开对应分类。
- **分类面板**：点击 chip 展开—— genre 分类行（电影/剧集拉 `/genre/{type}/list?language=zh-CN` 全量，综艺/动漫/纪录片为固定 10764/16/99）+ 最热门搜索值双列榜（`/trending/{movie,tv}/day` 或 `/discover?with_genres=X&sort_by=popularity.desc`）；**点不同 genre chip 实时切换榜单**（discover 真实请求，内存缓存）。
- **数据全部运行时真实获取**：右上角请求日志可见每笔 API 耗时；token 默认取仓库 `.env` 只读 token（可覆盖，localStorage 持久化）。

**【网络兼容发现（对真实落地关键）】** 实测当前网络 `api.themoviedb.org` / `image.tmdb.org` 不可达，而 TMDB 官方备用域名 **`api.tmdb.org` 完全可用**（真实数据验证：trending top1「求救信号」🔥112.9、discover 综艺 top1「我独自生活」）。demo 已做双域名自动回退（api.tmdb.org 优先）；海报加载失败优雅隐藏。真实落地时 tmdbService 的 API_HOST 需评估同样的双域名策略。

**【待拍板】** ① 面板展开时 hero **下移**（demo 现状）还是**覆盖** hero；② 热度口径用 popularity 原始值还是归一化（如 🔥1234）；③ 分类热度榜的桶规则（综艺/动漫/纪录片按 genre_ids 归类是否合意，跨类重复计入如何处理）；④ 默认面板常驻（首页加载即显示）还是保持折叠、点击才展开。

## Demo v2：方案 A2 按四点拍板重写（`demo-category-quick-access-a2-2026-09-06.html` 覆盖）

**用户拍板**：① 面板展开 hero 下移；② 热度 = popularity 原始值；③ 综艺/动漫/纪录片也要有自己的分类；④ 多分类命中重复展示即可；⑤ 默认面板首页加载即显示；⑥ 下方内容 3 行、1 行 3 列，首页只显示前 3 分类，右侧显示 2 个内容。

**【旧逻辑】** v1：默认面板为 5 行分类纵列；综艺/动漫/纪录片面板无子分类（单标签）；热榜双列排行 10 条。

**【新逻辑】**
- **默认「首页」面板（加载即显示）**：前 3 个热度分类（1 行 3 列卡：排名 + Σpopularity 热度 + 热度条 + 该分类最热门搜索值海报/标题/🔥）+ **右侧全站最热 2 个内容卡**（backdrop 大图 + 🔥 + ★）。
- **分类面板**：子分类行 + 主区 **3 行 × 3 列 = 9 个内容卡**（海报卡 + 排名角标 + 🔥popularity + ★）+ **右侧该榜 top2 内容卡**。
- **综艺/动漫/纪录片真实交叉子分类**（discover `with_genres=主,副` AND，全部实测有数据）：综艺 全部/家庭亲子(10764,10751 总794)/谈话(10764,10767 总871)/新闻(10764,10763 总101)；动漫 全部/动作冒险/喜剧(4902)/科幻&奇幻/儿童；纪录片 全部/历史/犯罪/音乐(12626)/战争；排行榜子分类 = 日榜/周榜/电影榜/剧集榜四种 trending 窗口。
- 多分类命中重复计入（桶规则天然如此）；hero 下移 = 面板在文档流中推挤。

## Demo v2.1：用户两条反馈修订（同名 demo 覆盖）

① **首页默认面板**：每个分类卡右侧从「top1 单条」改为**显示 3 条热门数据**（排名 + 28×40 小海报 + 标题 + 🔥popularity，取该分类 trending 聚合 top3）。
② **分类面板内容卡**：原 2:3 大竖版海报（列宽 ≈200px、图高 ≈300px）确实过大——改为**紧凑横排卡**：排名内联 + 海报 54×80（w185）+ 标题/年份/★ + 右侧 🔥 热度列，3 行 × 3 列布局不变；右侧 2 个内容卡 backdrop 从 w780 降为 w300、min-height 150→128。

## Demo v2.2：去掉面板右侧栏（用户选择方案 1）

用户问「每个 chip 下方最右侧为何有 2 个 card」——源头是上一轮拍板消息里「右侧显示2个内容」一句，被我理解为面板右侧固定 2 张大图内容卡。经确认该理解非用户本意，用户选择**去掉右侧栏**：面板主区（首页 3 分类卡 / 分类面板 3×3 内容卡）占满整行；sideCard 函数、`.qa2__body/.qa2__side/.sidecard-*` 样式与全部引用删除；catgrid/hotgrid 直接作为面板主体。跳转说明同步更正。

## Demo v2.3：修复「不是 3 行 × 3 列」

根因：v2.1 加的 `@media (width < 1500px)` 降级规则——用户浏览器窗口不足 1500px 时分类面板被降为 2 列、首页 catcard 被降为竖排 1 列。demo 本就只针对 >1280 桌面，整条降级规则删除：catgrid 恒 1 行 3 列、hotgrid 恒 3 行 × 3 列。
