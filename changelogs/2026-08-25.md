## 1. LazyImage 封面淡入失效修复：reveal 规则把 crossfade 的 pending 层压成 opacity:1

- 日期：2026-08-25
- 问题：首页/分类页卡片封面在分类切换（`crossfadeOnChange`）时，新封面从「旧图淡入替换」退化为「旧图消失、新图硬切」——280ms 交叉淡入完全不可见，观感为闪烁/跳变。
- 根因：CSS 特异性。`.lazy-image--pending { opacity: 0 }` 特异性为 0,1,0，而两条 reveal 规则 `.lazy-image-container.loaded.revealed .lazy-image`（0,4,0）与 `.lazy-image-container--cached.loaded.revealed .lazy-image`（0,5,0）会把**容器内所有 `.lazy-image` 子层**（含 base / pending）一律压成 `opacity:1` → pending 首帧即不透明、淡入无意义。该 reveal 规则是历史加入的（控制骨架容器推开后的终态），未考虑其与 crossfade 的双层结构冲突。
- 旧逻辑：
  - `.lazy-image-container.loaded.revealed .lazy-image { opacity:1; filter:blur(0); transform:scale(1); }`（0,4,0）
  - `.lazy-image-container--cached.loaded.revealed .lazy-image { opacity:1; transition: opacity 0.15s; }`（0,5,0）
  - pending 层 `opacity:0`（0,1,0）被以上两者压过 → new img 挂载即完全不透明显示。
- 新逻辑：给两条 reveal 规则的选择器加 `:not()` 排除交叉淡入的两层（specificity 不变，`:not()` 不贡献权重）：
  - `.lazy-image-container.loaded.revealed .lazy-image:not(.lazy-image--base):not(.lazy-image--pending)`（仍 0,4,0）
  - `.lazy-image-container--cached.loaded.revealed .lazy-image:not(.lazy-image--base):not(.lazy-image--pending)`（仍 0,5,0）
  - 效果：reveal 规则只锁定「单图路径」（仅 `lazy-image` 类）与占位/骨架，不再触碰 base/pending；pending 恢复 `opacity:0` → `is-loaded` 后经 `transition: opacity var(--lazy-crossfade, 280ms)` 平滑淡入（`.lazy-image--pending` 声明在 `.lazy-image` 之后、同特异性，transition 简写胜出）。
  - 边缘验证：单图路径（仅 `lazy-image` 类，无 base/pending）仍命中 `:not()` 条件 → 行为不变；fallback（`lazy-image lazy-image-fallback`）同理，无影响。
