# 2026-09-09 晚 · Play 页三面板折叠动画重做 + CMS 源管理失败态治理

## 1. 折叠动画重做（全端：桌面 ≥1024 / 窄屏 / App / TV）

- 旧实现两处硬伤：`body { transition: max-height .3s }` 阈值恒 80vh，内容远低于阈值时前段空转、尾段猛冲；≥1024 块给 `.player-panel-body.collapsed` 写死 `height: 0` 且无过渡 → 桌面端收起瞬跳。
- 新方案：新增 `hooks/usePanelCollapse.ts`（WAAPI from→to 精确高度动画）。展开 260ms `cubic-bezier(0.22,1,0.36,1)`；收起 200ms `cubic-bezier(0.4,0,0.2,1)`；箭头旋转同曲线；连点取动画中间高度作起点；`prefers-reduced-motion` 跳过；动画期间 `is-collapsing` 关 body 滚动防滚动条闪。
- CSS：`.player-panel { --panel-header-h }`（header 定高与收起态锁高同一真源）；`.player-panel.collapsed` 改为 `height: calc(var(--panel-header-h) + 2px)` + `grid-template-rows: auto auto` → body 保自然高度，内容被面板 `overflow:hidden` 从底部裁切/露出；全端所有 `.player-panel-body.collapsed` 的 `max-height:0 / padding:0 / height:0` 删除，只留 `border-top-width: 0`。
- **为什么不用纯 CSS `grid-template-rows: 0fr↔1fr`**：它只在容器高度 auto（内容驱动）时成立；桌面端面板高度由 sidebar 的 1fr 行分配（容器高度固定）→ fr 行恒填满 → 动画完全无效。

## 2. 全收起态「大空壳」修复

- `.player-sidebar--all-collapsed`（≥1024 块）补 `align-self: start` + `align-content: start`。旧 CSS 只写 `height/min-height: auto`，对两处 stretch 完全无效：侧栏作为 grid item 被拉满播放器高度，内部 3 条 `auto` 行又被 `align-content: stretch` 平分剩余高度。

## 3. ≥2200 滚动条不贴浏览器右侧

- 根因：`.player-page`（≥1024 自滚动容器）吃了 `--layout-content-max-width`（min(100%,2200px)）+ 居中 → 原生滚动条画在容器右缘，≥2200 起内缩。
- 修法：滚动容器铺满视口（`.player-page { max-width: none }`），封顶下沉到 `.player-main` / `.player-detail-section`：`--player-content-max: min(100%, calc(var(--layout-content-cap) - var(--page-pad-x) * 2))` + `width: 100%` + `margin-inline: auto`。
- ⚠️ 陷阱一：`min(100%,…)` 的 100% 基准是**内容盒**（已减留白），必须写 `min(100%, cap − 2×pad)`；`calc(min(100%, cap) − 2×pad)` 会把留白减两次。为此 variables.css 新增 `--layout-content-cap: 2200px` 裸值真源。
- ⚠️ 陷阱二（引入过回归）：flex item 只写 `margin-inline:auto` 会吃掉剩余空间使 `align-self:stretch` 失效 → `.player-main` 塌成 fit-content（264px），`1fr` 播放器列压成 0×0 → 1024–1449「播放器与面板都消失」。**铁律：flex item「居中 + 封顶」必须 `width:100% + max-width + margin-inline:auto` 三者齐写。**
- 附带修复：`.player-main` / `.player-detail-section` 加 `flex-shrink: 0`（固定高度 + `overflow:auto` 的 flex 容器里，压缩优先于滚动）。

## 4. CMS 源管理五连修

1. **切源不再显示骨架**：渲染分支 `cmsLoading && !video` 拆为「`!hasLoadedOnce` 才出骨架；切源中落到『无 currentSrc』分支」——CMS tab 保留、选中态保留，选季/选集面板显示 loading（新增 `loading` prop，spinner + 文案）。
2. **连点切源选中态消失**：双真因——`handlePlayCMSSource` 写 `activeSourceId(result.sourceName)`（`isActiveSource` 按 id 比较永不等）→ 改 `result.sourceId || result.sourceName`；旧请求返回回写 `setActiveSourceId` 覆盖新点击 → 引入 `reqSeqRef` 递增序号，只有「最新请求」允许写状态/收尾。
3. **失败/超时永久加载**：`fetchCMSSources` / `handlePlayCMSSource`(rebuild) / `loadSeason` 三处加 20s 超时兜底（abort + 强制收尾）；`fetchCMSSources` 顶部 `getVideoSources()` 裸 await 包 try/catch（原为未捕获 rejection → loading 永驻）。
4. **切季选集面板不更新**：主分支 inline `onSelectSeason` 只 `setSelectedSeason` 不取数 → 改接 `handleSelectSeason`；缓存命中分支「当前集号在新季不存在 → 回退首集 + 恒写 video」。
5. **失败不回退旧源数据**：`handlePlayCMSSource` 三处失败/无数据路径统一清空播放状态（video/sources/currentSrc/localEpisodeId/源名 ref）。

## 5. CMS 业务错误码校验（code != 1）

- `videoService.ts`：`CMSListResponse` 补 `code/msg`；新增 `assertCmsOk`（code 非 1 抛 `Error(msg)`）+ `fetchCmsList` 统一入口，9 处 `getJSON<CMSListResponse>` 全部替换。
- 实测例：`{code:1002, msg:"Current API forbids keyword search."}` 此前 HTTP 200 无 list，被吞成「未找到匹配资源」或按成功解析 → 面板骨架 / 播放器永久加载；现在走明确失败链路。
- 渲染守卫：入场骨架分支 `!video && !cmsLoading && !cmsSwitching` 补 `&& !hasLoadedOnce`——切源失败后落「暂无数据」空态（真实面板 + 空态文案），绝不回退骨架。
