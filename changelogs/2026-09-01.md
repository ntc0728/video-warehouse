## 5.1 首页 banner 缩略图点击跳转「复位到中间图再离开」修复
- 日期：2026-09-01
- 问题：点击首页 banner 右侧非中间缩略图跳转详情时，banner 主图会先复位到中间缩略图对应项再离开首页。
- 旧逻辑：`HeroBanner` 的 `handleDragStart`（mousedown 触发）直接进入三联 track 模式，但 track 中心恒为 `activeIndex`（中间缩略图对应项）。hover 预览期间主图显示的是 `hoveredIndex` 项，mousedown 后 track 强制以 `activeIndex` 为中心，主图被「闪回」到中间图。`hoveredIndex` 仅存 state，callback 闭包读不到最新值，无法在 mousedown 时提交。
- 新逻辑：新增模块级 `hoveredIndexRef`（渲染阶段同步），`handleDragStart` 内若检测到存在预览项且与 `activeIndex` 不同，先 `setActiveIndex(hovered) + setSwitchIndex(hovered)` 将预览项提交为 track 中心，再清空 `hoveredIndex` 进入拖拽模式。track 中心与当前显示项一致，主图视觉零变化，随后的点击跳转 / 拖拽翻页都从该项起算。
- 涉及文件：`src/components/HeroBanner/HeroBanner.tsx`
- 关联 Demo：无（行为修复，无布局/动画差异需对比）
- 构建：npm run build 通过

## 5.9 pipController 失败文案可读性 + 短路过慢/未加载视频
- 日期：2026-09-01
- 背景：用户报告「桌面端 + 浏览器移动端模拟，画中画点击后小窗看不到」。用本地 HLS（ffmpeg 生成）冒充真实流复现 → 真实播放下两端 PiP 均能正常打开（`document.pictureInPictureElement === video`，toast "已开启画中画"）。
- 推断真实场景：CMS 源/代理慢或失败时视频元数据不来，pipController 内部 timeout label（"等待视频元数据超时"）直接外泄到 toast → 用户既看不到小窗也得不到可执行提示，误以为"功能失效"。
- 新逻辑：
  1. `togglePip` 入口加快速短路：
     - `readyState===0 && networkState===NETWORK_NO_SOURCE` → "视频源加载失败，请切换其他源"
     - `readyState===0 && paused && !currentTime` → "视频尚未加载，请先开始播放"
  2. 内部 timeout label 改为短英文（"metadata"/"request"），外层 catch 兜底翻译为可读中文（"视频加载超时，请稍后再试" / "画中画请求超时，请重试"）—— 不再让 "等待视频元数据超时" 这种内部 label 直接外泄。
  3. 超时上调：`METADATA_TIMEOUT_MS 1500→3000`、`REQUEST_TIMEOUT_MS 3000→4000`，对慢网络更宽容。
- 验证：用 `pip-debug4.cjs`（本地 HLS 真实播放）跑桌面 + 移动端 → `pipEl:true` 成功；用 `pip-debug-fail.cjs`（route 打断 m3u8 让 readyState 卡 0）→ toast 变成 "视频源加载失败，请切换其他源"。
- 涉及文件：`src/components/UniversalPlayer/lib/pipController.ts`
- 关联 Demo：无（错误处理与文案）
- 构建：npm run build 通过
