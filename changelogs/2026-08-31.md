## 2. 播放器六项问题调研结论（只调研不改码，附修复建议）

- ① 更多设置弹窗修改后不关闭：chip 类走 `selectAndClose`（应用+toast+关闭），Switch 类「后台听视频/镜像翻转」onChange 漏调 `onClose()`；字幕开关开启时刻意不关（便于进入子设置）。
- ② 后台听视频：**未实现（假开关）**——`usePlayerStore.backgroundPlay` 仅 UI 存取，全仓库零消费点；`mediaSession` API 全仓库零引用。方案：P1 MediaSession 集成 → P2 iOS ManagedMediaSource/后台保活 → P3 Android 原生前台服务。
- ③ CMS 源折叠面板 tab 文本溢出：桌面 `.player-cms-list` 固定 3 列 grid 均分 + `.player-cms-name` `overflow:hidden+ellipsis`（Player.css:240）；移动端 `.player-cms-item` `max-width` 钳制 1/6 行宽（Player.css:797 区块，注释声称「不截断」是错的）。
- ④ 桌面切页签画面冻结：`usePlayerCore.ts:162-180` 已有 Issue2 修复（95c36a1，**未推送**），但手段无效——`video.play()` 幂等 no-op、同值 `style.transform` 重写不触发重绘；且 video 带 `transform`（镜像/4:3/16:9）或 `filter`（色彩调整）时是合成效果层（PlayerCore.tsx:58-71），Chromium 后台恢复不栅格化的经典冻结面。后台期间画面冻结为浏览器固有行为，Web 无法让隐藏页签持续渲染。
- ⑤ 预加载：`useNextEpisodePreload` hook 已实现且接入（Player/index.tsx:190），URL 与实际播放完全一致（同 `sources.find(isDefault)||sources[0]` 规则），vitest 8 用例全过；但只预拉「清单+首分片」且依赖源站缓存头，体感收益有限——「没实现」是效果误判，「实现了」是效果夸大。

## 3. 播放器四项修复 + 画面比例重构

- 日期：2026-08-31
- 问题：① 移动端更多设置弹窗 Switch 类改完不关；② CMS 源 tab 文本被截断；③ 桌面切页签画面冻结；④ 后台听视频是假开关；⑤ 画面比例实现不合理。
- 修复：
  - **① MobileMoreSheet**：后台听视频/镜像翻转/字幕开关三处 Switch 的 onChange 补 `onClose()`（与 chip 类 `selectAndClose` 行为一致）。字幕开关不再「开启不关」——改完即关，需进子设置再重开。
  - **② Player.css CMS tab**：基础规则 `grid repeat(3,1fr)` → `flex flex-wrap`，删除移动端/app 媒体查询的 `max-width: 1/6行宽` 钳制副本（旧注释「按钮文字不截断」与实际行为不符，已废弃）。tab 按内容自适应宽度，放不下自动换行。
  - **③ usePlayerCore 冻结修复**：visibilitychange 兜底从「同值重写 transform + offsetWidth」（不产生样式变化、对合成层无效）改为「追加 translateZ(0)，两帧后还原」——制造真实样式变化强制合成层失效重建。
  - **④ useMediaSession hook**：新建，锁屏媒体卡片（标题/副标题/进度）+ 媒体键 play/pause/seekbackward/forward/previoustrack/nexttrack；`backgroundPlay` 开关驱动（关闭则不注册元数据）。usePlayerCore 接入、UniversalPlayer 接线（点播=影片名+集名，IPTV=频道名）。
  - **⑤ PlayerCore 画面比例重构**：4:3/16:9 从 `objectFit:contain + translateX/Y(-50%)` 改为 `objectFit:fill + margin:auto`。理由：① contain 只加黑边、比例选择不改变画面几何，无法纠正 CMS 源 DAR 元数据错误；② 移除 translate transform 减少视频合成层（与冻结根因相关）。镜像 scaleX(-1) 保留。
- 涉及文件：`useMediaSession.ts`(新)、`usePlayerCore.ts`、`PlayerCore.tsx`、`MobileMoreSheet.tsx`、`UniversalPlayer.tsx`、`Player.css`、`player.spec.ts`
- 测试：M02/M03 通过（字幕开关行为变化已同步更新断言）；M07/M10 失败经 git stash 验证为既有 flaky 像素断言（改动前已失败，非本次引入）
- 构建：`npm run build` 通过

## 4. 后台听视频 P2（iOS 检测）+ P3（Android 原生前台媒体服务）

- 日期：2026-08-31
- 问题：后台听视频此前是假开关（P1 MediaSession 已在上一提交落地，但 iOS 后台续播、Android App 切后台音频中断未处理）。
- 实现：
  - **P2 iOS 检测**：`backgroundAudioService.ts` 新增 `getIOSBackgroundAudioCapability()` → iOS 17+ ManagedMediaSource 可用 = `supported`（HLSAdapter 已配 preferManagedMediaSource，后台续播由浏览器保证）/旧 iOS = `unsupported`（切后台必停，前端无法绕过）/非 iOS 或 Android App = `irrelevant`。`MobileMoreSheet` 后台听开关在 `unsupported` 时提示「切后台会暂停，建议升级 iOS 17+」。
  - **P3 原生前台服务**：
    - 前端：`backgroundAudioService.ts` 定义 `MediaBridge` 契约 + `getMediaBridge()` + `isNativeMediaServiceSupported()`；`useMediaSession` 监听 `visibilitychange`，Android App 切后台 `bridge.start`+`seek`+`play` 接管音频、暂停 video；切回前台 `bridge.stop`+恢复 video。
    - 原生（与 CastBridge 同体系）：`MediaService.java`（前台 Service + MediaPlayer 独立解码 + MediaSessionCompat 锁屏控制 + MediaStyle 前台通知，API 22–34 兼容）+ `MediaBridgePlugin.java`（Capacitor 插件驱动 Service）+ `MainActivity` 注册/shim 注入。
    - `patch-android-dlna.ps1` 追加 `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE` 权限 + 声明 `MediaService`（specialUse 类型 + PROPERTY_SPECIAL_USE_FGS_SUBTYPE）。
- 涉及文件：`backgroundAudioService.ts`(新)、`useMediaSession.ts`、`usePlayerCore.ts`、`UniversalPlayer.tsx`、`MobileMoreSheet.tsx`、`MediaService.java`(新)、`MediaBridgePlugin.java`(新)、`MainActivity.java`、`patch-android-dlna.ps1`、`AGENTS.md`
- 构建：`npm run build` 通过；player.spec M02/M13 通过
- 关联：P1（MediaSession）已在上一个提交落地，P3 是 P1 的 Android 兜底

## 5. 截图提示居中靠上 + 移动端避让 header + 更多弹窗跳变修复

- 日期：2026-08-31
- 问题：
  - ① play 页截图失败/成功提示显示在播放器容器正中心，遮挡视频主体，用户要求改为「居中靠上」。
  - ② 移动端播放器顶部有 up-player-header（返回栏 + 右上角操作组），居中靠上的提示会与 header 重叠，需下移避让。
  - ③ 鼠标悬浮在控制栏「更多设置」图标上时，弹窗先出现在错误位置再跳到正确位置（「移动一次」）。
- 旧逻辑：
  - ①② `PlayerToast.tsx` 的 `showCenter` 位置由 useLayoutEffect 测量：`y = rect.top + rect.height / 2`（正中心），无 header 避让；仅在挂载/resize/scroll 时测量，提示显示前不重新测量。
  - ③ `MoreMenu.tsx` 的 `pos` 初始为 null，弹窗首帧以 `top:auto/left:auto`（fixed + auto = 视口左上角）渲染，useLayoutEffect 测量后 setPos 移到正确位置；portal 到 body 的跨容器 commit 间可能被 paint 一帧，用户看到跳变。
- 新逻辑：
  - ① 新增 `measureCenterPos()` useCallback：垂直位置从正中心改为 `rect.top + rect.height * 0.3`（居中靠上，约 1/3 高度处，不遮挡视频主体）。
  - ② 移动端（`mobileCenter=true`，即真实移动设备）测量 `.up-player-header` 高度，`y = max(30% 位置, rect.top + headerH + 12px)`，确保提示在 header 下方 12px；`showCenter` 调用时先执行 `measureCenterPos()` 重新测量，保证 header 可见性刚变化时位置最新。
  - ③ `MoreMenu.tsx` 的弹窗 style 增加 `visibility: pos ? 'visible' : 'hidden'`：位置未计算好前隐藏，useLayoutEffect 测量（visibility:hidden 不影响 getBoundingClientRect 尺寸）后 setPos，再显示，消除首帧跳变。
- 涉及文件：`src/components/UniversalPlayer/PlayerToast.tsx`、`src/components/UniversalPlayer/ControlBar/MoreMenu.tsx`、`src/components/UniversalPlayer/UniversalPlayer.css`（注释更新）
- 测试影响：未改变 CSS 类名/DOM 结构/选择器，`player.spec.ts` 截图提示用例（如有）不受影响；无需新增测试。
