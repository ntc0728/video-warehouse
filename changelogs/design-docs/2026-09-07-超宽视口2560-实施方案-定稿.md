## T2 · G2 方案 A：≥2560 字号补偿（`--ui-scale: 1.08`）

### 现状根因
段2 字号是递减曲线，2200 冻结在地板值：base 13 / sm 12 / xs 11 / 2xs 10.33px（variables.css:494-500）。2560 @100% dppx 下物理偏小——这是「文本不清晰」的**主因**。

现有 `--ui-scale` 机制：
- 默认 1（variables.css:40 `:root`）；
- 自动档恒 1：`@media (width >= 1920px) and (resolution < 1.5dppx)` → variables.css:589-593；
- 手动档：`AppLayout.tsx:135-142`，`uiScale > 0` 时写 `<html>` 内联 `--ui-scale`（内联优先于任何 @media）；
- 所有 `--text-*` token 都乘 `var(--ui-scale)`；R3 契约 token 不乘 → 天然不受影响；TV 走独立 `[data-device="tv"]` 2× 曲线。

### 改动（`src/assets/styles/variables.css`，**必须放在 589-593 块之后**——同特异性后写胜出）

```css
/* ═ U-1（2026-09-07 G2-A）：≥2560 大屏字号补偿档 ═
   手动档（AppSettings.uiScale 内联）始终最高优先；
   resolution < 1.5dppx 与既有自动档口径一致——高分屏（系统缩放 ≥150%）
   CSS px 密度已足够，不叠加补偿。 */
@media (width >= 2560px) and (resolution < 1.5dppx) {
  html:not([data-device="app"]):not([data-device="tv"]) {
    --ui-scale: 1.08;
  }
}
```

### 影响面与风险
- `--text-base` 13 → 14.04px，全站字号/图标（--icon-* 派生自 --text-*）+8%。
- R3 五个契约（sidebar-width / logo-size×3 / header-height）不乘 scale → 不变。
- 撑高排查清单（真机 2560 逐项过）：顶栏 SearchBox（`--comp-input-height-header` 40→48 专用矮曲线、不乘 scale，字变框不变 → 需目测）、导航 tab、播放页侧栏 `--comp-tab-h`。
- 手动档用户设任意值（含 1.0）时内联覆盖本档 → 行为正确。

### 验收
- 2560 @100%：`getComputedStyle(document.documentElement).getPropertyValue('--ui-scale')` = 1.08，`html` 字号 ≈14px。
- 设置页手动缩放仍生效（内联优先）；1920/1440/TV/App 全部不变。

## T3 · G3 边框过浅 + 文本对比度（≥2560 两档）

### 归因结论（沿用调研）
1. **字号是主因** → T2 解决。
2. **颜色是次因**，浅色主题下：
   - `--color-border` `#d9d9d9`（variables.css:78）对 `#fff` ≈ **1.57:1**（WCAG 非文本建议 ≥3:1）——搜索框输入框、tab/chip 描边过浅的直接原因；
   - `--color-border-light` `#e8e8e8`（:79）≈ 1.33:1；
   - 未激活 tab/chip 文字用 `--color-text-tertiary` `#999` ≈ 2.85:1（文本建议 ≥4.5:1）。

### 改动

**① token 提档**（`variables.css`，紧跟 T2 新块之后；浅色专属三重排他）：

```css
/* ═ U-2（2026-09-07 G3）：≥2560 边框对比度提档（浅色主题限定）═══
   搜索框 / tab / chip 描边 1.57:1 → 3.0:1；卡组浅边框 1.33:1 → 1.9:1。
   仅 ≥2560 生效：1440 基线与暗色主题零变化。 */
@media (width >= 2560px) {
  html:not([data-theme="dark"]):not([data-device="app"]):not([data-device="tv"]) {
    --color-border: #bfbfbf;       /* = 既有 --color-border-strong 取值 */
    --color-border-light: #dedede;
  }
}
```

> token 覆写方式让 SearchBox 输入框、`.browse-search-tab`、`.filter-bar__chip`、`.category-segmented__item`、IPTV 分组 chip 等**所有消费 `var(--color-border)` 的描边一次性提档**，无需逐组件改。暗色主题边框 `#363636` 对深底对比本就足够，不覆盖。

**② 未激活 tab/chip 文字提档**（`index.css` 新「超宽视口」段）：

```css
/* ═ U-3（2026-09-07 G3）：≥2560 未激活 tab/chip 文字 tertiary(#999,2.85:1)→secondary(#666,5.7:1) */
@media (width >= 2560px) {
  html:not([data-theme="dark"]):not([data-device="app"]):not([data-device="tv"])
    .browse-search-tab,
  html:not([data-theme="dark"]):not([data-device="app"]):not([data-device="tv"])
    .category-segmented__item,
  html:not([data-theme="dark"]):not([data-device="app"]):not([data-device="tv"])
    .filter-bar__chip,
  html:not([data-theme="dark"]):not([data-device="app"]):not([data-device="tv"])
    .filter-bar__label--clickable {
    color: var(--color-text-secondary);
  }
}
```

> 实施时先 grep 上述四个类名的实际未激活色声明位置，确认没有更高特异性的 `.active` 覆盖冲突（active 态均为黑底白字或 `--color-text`，不受影响）。

### 验收
- 2560 浅色：SearchBox 输入框边框 `#bfbfbf`；未激活 chip 文字 `#666`；与 demo V2 的 G3 对照一致。
- 1440 浅色：边框仍 `#d9d9d9`；暗色主题（任一视口）：仍 `#363636`。
- `--color-border-strong` hover 加深逻辑不受影响（覆盖值 = strong 值，hover 态如有进一步加深需目测一处）。

## T4 · Play P-A：播放器封顶 1920 · 16:9

### 现状根因
- Player.css:1 `.player-page` = `min-height:100dvh` 纵向 flex；:11 `.player-main` flex 行、`height:100%`；:19 `.player-video-area` `flex:1; height:100%` → 2560 下视频面 ≈ **2200×1372（页面满屏）**，侧栏 320px（`--layout-sidebar-width` R3 契约，不动）相形过窄。
- `.player-main` 有 `margin: 0 calc(-1 * var(--space-sm))`（:15）抵消页 padding 贴边。

### 改动（`src/pages/Player/Player.css` 末尾新增）

> **阈值终版（用户 2026-09-07 16:09 复核）：P-A 维持 `width >= 2560px`**（16:09 曾改 ≥1440，16:09 后改回）；BR-C 维持 ≥1440。

```css
/* ═ P-A（2026-09-07 G-Play）：≥2560 播放器封顶 1920 · 16:9 ═
   无损方案：等比缩放（letterbox 不可见——底色同为 #000），
   侧栏宽度走 --layout-sidebar-width 契约不动。
   <2560（含 1440 基线）不生效。 */
@media (width >= 2560px) {
  html:not([data-device="app"]):not([data-device="tv"]) .player-main {
    width: 100%;
    max-width: 1920px;
    margin-inline: auto; /* 覆盖 :15 负 margin：两侧留白对称 */
  }
  html:not([data-device="app"]):not([data-device="tv"]) .player-video-area {
    aspect-ratio: 16 / 9;
    max-height: 1000px;   /* 兜底：防极端宽高比 */
    align-self: center;   /* 垂直居中，下方留呼吸空间 */
  }
}
```

### 关键点
- 2560 下视频面实测 ≈ 1580×889（1920 − 侧栏 320 − gap），垂直居中于剩余高度。
- 全屏不受影响：`:fullscreen` 作用于 `.player-video-area` 本身（Player.css:29 已处理圆角），aspect-ratio 在全屏替换布局中不生效。
- 侧栏内部（面板/剧集格）不动；侧栏高度仍随 `.player-main` 拉满——如验收觉得侧栏过长，二期再议侧栏自适应。
- `<2560`（含 1440 基线）、TV、移动（`width < 1280px` 纵向堆叠分支 Player.css:64）零变化。

### 验收
- 2560：视频居中 16:9、无拉伸（hls 画面 `object-fit` 正常）、全屏进出正常、Hot Switch 冷热切换无布局跳动。
- 1440：视频面与改动前逐像素一致。

## T5 · Browse BR-C：≥2560 侧栏筛选

### 现状
- `Browse/index.tsx:334-408`：`.browse-page` > `.browse-card--search`（内含 `.browse-search-tabs` + `<FilterBar>`）+ `.browse-card--results`（内含 `.browse-sort-bar` + 结果栅格）。
- FilterBar 根类 `.filter-bar`（FilterBar.css:10），行结构 `.filter-bar__row`，chip 横向滚动 `.filter-bar__chips-scroll`。
- 筛选状态全在 `useBrowseData.ts`（URL ↔ FilterBarValue）——**BR-C 纯 CSS 重排，数据层零改动**。

### 改动（`src/pages/Browse/Browse.css` 末尾新增；CSS-only，不改 TSX）

> **阈值修订（用户 2026-09-07 16:06 拍板）：BR-C 生效范围改为 `width >= 1440px`。**
> 连带影响：1440 桌面端直接由「堆叠筛选」切换为「侧栏筛选」；<1440 维持现行布局。

```css
/* ═ BR-C（2026-09-07 G-Browse）：≥1440 侧栏筛选 ═
   原理：search 卡 display:contents 解体，三个子块由 .browse-page grid 重排；
   results 卡整体占右列，筛选面板 sticky 左列。 */
@media (width >= 1440px) {
  html:not([data-theme="dark"]):not([data-device="app"]):not([data-device="tv"])
    .browse-page:not(.browse-page--mobile):not(.browse-page--tv) {
    display: grid;
    grid-template-columns: 264px minmax(0, 1fr);
    grid-template-areas:
      "tabs    results"
      "filters results";
    gap: 0 24px;
    align-items: start;
  }
  html:not([data-device="app"]):not([data-device="tv"]) .browse-card--search { display: contents; }
  html:not([data-device="app"]):not([data-device="tv"]) .browse-search-tabs { grid-area: tabs; }
  html:not([data-device="app"]):not([data-device="tv"]) .browse-card--results { grid-area: results; }
  html:not([data-device="app"]):not([data-device="tv"]) .filter-bar {
    grid-area: filters;
    align-self: start;
    position: sticky;
    top: calc(var(--header-height, 64px) + 20px);
    /* 面板化：补回 display:contents 丢掉的卡片 chrome */
    flex-direction: column;
    background: var(--color-surface);
    border: 1px solid var(--color-border-light);
    border-radius: var(--radius-lg);
    padding: 16px;
    box-shadow: var(--shadow-card);
  }
  /* 侧栏内禁横向滚动 → 换行堆叠 */
  html:not([data-device="app"]):not([data-device="tv"]) .filter-bar__row { flex-direction: column; align-items: stretch; }
  html:not([data-device="app"]):not([data-device="tv"]) .filter-bar__row--scroll,
  html:not([data-device="app"]):not([data-device="tv"]) .filter-bar__chips-scroll {
    overflow-x: visible;
    flex-wrap: wrap;
  }
}
```

### 关键点与已知取舍
1. `display: contents` 使 `.browse-card--search` 自身的卡片边框/阴影在 ≥1440 消失——tabs 裸排、filter-bar 面板化补偿；`.browse-card--results` 的 chrome 保留（它整体进右列）。
2. `.browse-search-tabs` 在通栏（tabs 区）后，原「双卡相连」视觉（Browse.css:53）在 ≥1440 不存在——属 BR-C 设计意图。
3. `minmax(0, 1fr)` 防止结果栅格被内容撑破 grid 列。
4. 窗口缩到 <1440 → media 失效，`display:contents`/grid 全部回落，现行布局零残留。
5. TV/移动由 `:not(.browse-page--mobile/--tv)` + 设备前缀双保险排除。

### 验收
- ≥1440：左侧 264px sticky 筛选面板（类型/地区/年份竖排换行），右侧结果栅格通栏；筛选操作后 URL 参数变化与现状一致（`useBrowseData` 未动）。
- 窗口 1439→1440 拖动：布局平滑切换无闪烁；<1440 逐像素回归。
- FilterBar 行内 `--label-as-chip` 模式（FilterBar.css:40）在竖排下的观感需真机确认一处。
