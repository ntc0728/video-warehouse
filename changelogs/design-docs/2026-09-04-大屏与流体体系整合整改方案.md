## 1. 冲突与影响分析（流体整改 × 大屏方案）

对两份方案逐项交叉比对，结论：**方向一致、无结构性冲突，但有 5 处必须调整**。

### 1.1 ⚠️ `--ui-scale` 1.15 的前提已失效 → 幅度必须重新校准（最重要的冲突）

1.15 是在「R1 恒 MIN、桌面基线只有设计值 43%」的前提下定的——**它实际承担的是「恢复基线 + 大屏放大」双重职责**。三段式落地后基线本身恢复（1920 达 MAX），1.15 若原样叠加会过头（`--space-lg` 28×1.15=32.2px，超出设计意图）。

**处置**：`--ui-scale` 职责收窄为「纯大屏增强层」，幅度移至 **阶段 D 真机重感后校准**（预判区间 1.0~1.15，可能远小于 1.15 甚至不需要）。自动档阈值 D2（≥1920 且 dpr<1.5）不变，仅默认幅度待定。**这不是推翻 D4，而是 D4 的前提被 D5-D7 修正后的必然结果。**

### 1.2 `--text-base` 变流体 → rem 全局流动 14→16（D7 的连带影响，必须显式管理）

`index.css:259` 是 `html { font-size: var(--text-base) }`，`--text-base` 变为 `clamp(14px,…,16px)` 后 **rem 不再恒 14，随视口 14→16 流动**。影响三路：

| 通道 | 现状 | 整改后 | 处置 |
|---|---|---|---|
| Tailwind 语义档（`text-sm`/`p-md` 等） | 已重定向到 token（tailwind.config.js:40-54） | 自动跟随新 token，**无额外工作** | 无 |
| Tailwind 数字档（`gap-4`/`w-8`/`rounded-lg` 等） + 自写 CSS **547 处 rem** | rem 恒 14 → 全部比 16 基准**偏小 12.5%（既有隐性 bug）** | 随视口流动，大屏恢复设计比例 | **接受流动**——这本身就是全局等比缩放的一部分；但 R7 收编时其内部 rem 一律换算成 px（§4-B），避免二次流动 |
| 流体 token 的 PREF | 用 rem 写 → 桌面偏小 12.5% | PREF 全改 **px 字面** | 阶段 A 执行 |

**结论：rem 流动方向正确（顺带修复 Tailwind 数字档 12.5% 偏小），但必须防止「token 内流动 + rem 端点流动」叠加，R7 与新 token 定义中的 rem 全部清除。**

### 1.3 两段线性无法用单条 clamp 表达 → 实现方式定稿

三段曲线 = 两条单段线性规则的叠加（交接点 768 连续）：

```css
:root {                          /* 段1：375→768，MIN → A */
  --space-lg: clamp(12px, 4.833px + 1.910vw, 22.667px);
}
@media (min-width: 768px) {      /* 段2：768→1920，A → MAX */
  :root {
    --space-lg: clamp(22.667px, 15.314px + 0.956vw, 28px);
  }
}
```

- 每个流体 token 两条规则（`:root` + `@media(min-width:768px)` 内 `:root`），87 个 token ≈ 174 条。
- **A 值（768 交接点）**：`A = MIN + (MAX − MIN) × R`，统一取 **R = 2/3**（移动段走完 2/3 行程，桌面段补完剩余 1/3）。R 为全局唯一可调参数，阶段 D 校准时只改生成脚本一处重跑。
- TV 不受影响：`html[data-device="tv"]` 块（specificity 0-1-1 + 源序在后）覆盖 `:root`。
- 87 条两段定义由**脚本生成**（解析现有 token → 计算 → 重写 variables.css 对应行），禁止手写。

### 1.4 `--layout-content-max-width` 的双重身份

它既在 R2 名单（MIN 320 / MAX 1920），又是 D4 内容区硬上限 2200 的载体。**处置：从 R2 统一契约中豁免，单独定契约**：`320 → 2200`，锚点 375→3847（与大屏方案 §2200 一致，流体段保证小屏可用性）。同批豁免复核：`--layout-osd-max-width`、`--layout-hero-height`、`--layout-modal-max-width`（D8 的「语义特殊」名单）。

### 1.5 时序依赖决定整改顺序（原一期「先落 ui-scale」路线作废）

`--ui-scale` 乘在新 token 外层才生效；R7 收编必须引用新 token 才有意义；内容区 token 是 R2 成员。依赖链：**token 重定义（A）→ R7 收编（B）→ 大屏机制（C）→ 校准（D）**。一期方案中「先上 1.15 + 卡片封顶」的原顺序废弃，并入下述阶段。

其余一致项（无需调整，双方方案已同向）：撤销 `variables.css:404` gap 覆盖（消灭 grid-gap 1919→1920 +96.7% 跳变）；R3 五个不动；R4 TV 独立不动；R6 兜底不动；新增 `@media(≥1920)` 网格规则必须带 `html:not([data-device="tv"])` 前缀。

## 2. 整改后 token 体系总览

| Regime | 数量 | 整改动作 | 阶段 |
|---|---|---|---|
| R1 375→768 契约流体 | 41 | 重写为三段式（MIN/MAX 保留，PREF 改 px 字面） | A |
| R2 PREF=MIN 无契约 | 46 | 重写为三段式（统一契约 R=2/3；4 个豁免单复核） | A |
| R3 真实独立契约 | 5 | **不动** | — |
| R4 TV 视口映射 | 61 | **不动**（独立体系，零回归） | — |
| R5 @media 阶梯 | 9 档 | `--card-cols` 竖向消费点改 auto-fill（C）、横向行保留数值仅重算（C）、gap 覆盖删除（A） | A/C |
| R6 大屏兜底 2× | 6 | **不动** | — |

## 3. 整改顺序（正确流程，共 6 阶段）

> 每阶段独立 commit、独立可回退（`git revert <commit>`）；每阶段完成即补录 `changelogs/当日.md`。

### 阶段 0 · 基线快照（半天）
1. 全量 E2E 跑通并记录基线（267 条/19 spec），标出**视觉 px 断言清单**（粗计 `toHaveCSS`/`boundingBox` 类 25 处，阶段 A 后重点回归对象）。
2. Playwright 对 `/`、`/browse`、`/history`、`/detail`、`/play` 在 **1280 / 1920 / 2560 / 3440** 四视口截屏存档（`/tmp/vis-baseline`，不入库）。
3. 建立对比 demo 基线值（现有 demo-fluid-regimes / demo-clamp-coeff-fix 已含）。

### 阶段 A · 三段式 token 重定义（核心，1~2 天）
1. 写生成脚本 `scripts/gen-fluid-tokens.py`：解析现 `variables.css:37-374` → 按 §1.3 公式输出两条规则/ token → 原位重写。
   - R1 41 个：MIN/MAX 保留，契约恢复（`COEFF=(MAX−MIN)/393` 段1 + `(MAX−A)/1152` 段2）。
   - R2 46 个：同公式；`--layout-content-max-width` 等 4 个豁免单定契约（§1.4）。
   - `--text-base`：`clamp(14px, …, 16px)` 契约 375→1920（D7）。
   - 全部外层包 `calc(… * var(--ui-scale))`；`:root { --ui-scale: 1 }`。
2. 删除 `variables.css:404` 的 `@media(≥1920)` gap 覆盖（R5-R7 类跳变源）。
3. `npm run build` → E2E 全量 → 修视觉断言（预期集中在 25 处 px 断言 + 布局类）。
4. **验收**：端点校验 375=MIN / 480 流体 / 1920=MAX / 2560=MAX；`--grid-gap` 跨 1920 无跳变；TV 四视口回归零 diff；对比基线截图。

### 阶段 B · R7 组件级收编（51 处 / 16 文件，1~2 天）

收编决策规则（按序命中）：
- **a. 端点已是 token**（如 `AppLoading.css:69` `clamp(var(--text-2xl),…,var(--text-3xl))`）→ 保留结构，仅把**中项 rem 改 px 字面**（×16 设计基准换算）。
- **b. 语义与现有 token 重合** → 直接换 token。已确认重合：`Layout.css:3 --sidebar-width` ≈ R3 `--layout-sidebar-width`；`IPTVOSDBar.css:553` 本就在覆写 `--layout-osd-max-width`（改为引用）。
- **c. 纯 rem/px 硬编码** → 按语义归组建新 token（归组预判，实施时定稿）：
  - 图标/按钮尺寸族（StillsLightbox 12 处、Detail 8 处、TMDBMovieRow/History/UniversalPlayer 若干）→ `--icon-*` 派生体系或 `--comp-*` 新档位；
  - 版面尺寸族（Person 8 处头像/看板、RecordShell、SearchBox、SourceStatusIndicator、Settings、Home、Player）→ `--layout-*` 新档位；
  - 全部 rem 端点 ×16 转 px，杜绝二次流动。

分布：StillsLightbox 14 / Detail 8 / Person 8 / Home 4 / AppLoading 3 / UniversalPlayer 3 / HeroBanner 2 / 其余 8 文件各 1（Layout、RecordShell、SearchBox、SourceStatusIndicator、TMDBMovieRow、IPTVOSDBar、History、Player、Settings）。
（注：审计报告粗记「53 处/11 文件」，本轮精确扫描为 **51 处/16 文件**，以本清单为准。）

**验收**：`grep -rn "clamp(" src --include=*.css` 在 variables.css 之外归零；build + E2E 通过。

### 阶段 C · 大屏机制落地（1 天）
1. 内容区：`--layout-content-max-width` MAX 2200（阶段 A 已定契约）；`AppLayout` 主内容容器接入（当前仅 CategoryQuickAccess 消费）。
2. 卡片封顶：新增 `--card-size: calc(290px * var(--ui-scale))`；竖向网格改 `grid-template-columns: repeat(auto-fill, var(--card-size))` + `justify-content:center`（History / VideoCard / SkeletonCard / Person / Detail 等 `repeat(var(--card-cols))` 消费点；Skeleton 与真实卡同规则，天然防 FOUC）。
3. 横向滚动行：保留 `--card-cols` 数值，重算断点（≥2560：9→6、≥3840：10→6，按 `(2200+gap)/(333.5+gap)`）；`TMDBMovieRow.css:107`、`Home.css:441` 的 calc 依赖随之复核。
4. 自动档：`@media (min-width:1920px) and (resolution < 1.5dppx) { html:not([data-device="app"]):not([data-device="tv"]) { --ui-scale: <阶段D校准值> } }`。
5. 手动档：`AppSettings.uiScale`（0=自动）→ `AppLayout` 写 `<html>` 内联 `--ui-scale`（内联优先级天然覆盖自动档）→ AppearanceTab 档位 UI（仅非 TV 显示）。
6. **验收**：2560 单卡 ~333px 恒定、列数 6；1920 单卡 ~333px、列 5；两侧留白 ≤210px；TV 零影响。

### 阶段 D · 真机校准 `--ui-scale`（用户参与）
1. 阶段 A-C 全部落地后，用户在 **24/27/32 寸真机**重感（此时基线已恢复，感受与 9-04 上午完全不同）。
2. 拍板：自动档默认幅度（预判 1.0~1.15）；手动档档位集是否调整（初始 100/110/115/130/150）。
3. 若 1.15 原值仍成立则不动；否则只改自动档常量 + 手动档默认值，**一处改动一次 commit**。

### 阶段 E · 收尾（半天）
1. 公共文档同步：`KNOWLEDGE.md` 更新日志（token 体系 v2）、`TEST-CASES.md` 增补端点/封顶用例、E2E 计数表校准。
2. demo 索引与 changelog 终稿；删除过渡 demo 中已失效的对照面板（保留审计 demo 作为历史档案）。
3. 三期（TV `--tv-scale` + 列数按占屏比封顶）另行排期，不在本方案。
