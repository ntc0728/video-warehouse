# ≥2560px 超宽视口 UI 适配整改方案（2026-09-07）

> 状态：**调研完成，未改任何业务代码**。全部方案为提案，等用户拍板后再实施。
> 配套可运行 demo：`changelogs/demos/demo-ultrawide-2560-adapt-2026-09-07.html`
> 基准口径：2560×1440 @dpr 1.0（此时全部 token 已在 2200 冻结、内容区封顶 2200、--page-pad-x=140）。

---

## 〇、根因总览（先看这个）

大屏问题不是「token 没适配」，而是 **2200 冻结点之后的三类「比例断裂」**：

| # | 断裂 | 机制 | 证据（file:line） |
|---|------|------|-------------------|
| 1 | **宽度断** | 6 个页面接了 2200 内容上限，其余页面全宽拉伸 → 同屏根宽 2200 vs 2280 不一致 | 接入：Browse.css:13 / Person.css:11 / Home.css:32 / Collections.css:12 / History.css:345；**未接入：IPTV.css:1-7、Detail.css:8-14、Player.css:1-9、Chart.css:8**；上限定义 variables.css:429 |
| 2 | **字号断（偏小）** | 字号段2是递减曲线，768→2200 越大越小，2200 冻结在地板值：base 13 / sm 12 / xs 11 / 2xs 10.3px | variables.css:493-500 |
| 3 | **容器断（偏大）** | 大量「高度类」尺寸不走 token，用 vh/vw 独立曲线，2200 之后**继续增长**：Detail hero、Person hero、Player 100dvh | Detail.css:24-33、Person.css:23-34、Player.css:1-27、variables.css:862-872 |

**结论（用户三个疑问的直接回答）：**
1. 「一些字号偏小」= 冻结地板值（12–13px）在 2560 物理像素下偏小；
2. 「一些字号/元素偏大」= 不是字号变大，是**未封顶容器继续变大 + 间距族冻结在 MAX**（space-xl 27 / 2xl 37 / 3xl 52px，variables.css:474-476），衬得版面空旷巨大；
3. 「文本不清晰」主因是**字号**（11–13px @100% dpr），边框辨识度是**颜色**问题，两者独立：
   - `--color-border` #d9d9d9 对 #fff 对比度 **≈1.57:1**（远低于 WCAG 3:1 非文本下限）→ SearchBox.css:87、FilterBar.css:135、GroupPicker.css:11 全用它；
   - `--color-tab-inactive-text` #a0a0a0 对 #fff **≈2.6:1**（低于 4.5:1 文本线）→ variables.css:97。
   - 正文 #666（≈5.7:1）对比度合格，不清晰纯粹因为小。

## 一、【全局】整改方案

### G1. 内容宽度公共壳（新增组件，不改 2200 上限）

**设计思路**：把「2200 封顶 + 居中」抽成公共类/组件，未接入页面逐个挂上；**2200 数字本身不动**（红线）。超宽页面（Player 等）允许用更小的专属上限「进一步缩小内容主题宽度」。

```css
/* index.css 新增（不动 --layout-content-max-width 定义） */
.content-shell {
  width: 100%;
  max-width: var(--layout-content-max-width); /* min(100%, 2200px)，定义不动 */
  margin-inline: auto;
}
/* 主题内容更窄的专属档（demo 中可调） */
.content-shell--narrow { max-width: min(100%, 1920px); }
```

| 页面 | 现状根宽 @2560 | 建议 |
|------|----------------|------|
| IPTV / Chart | 2280 全宽 | 挂 `.content-shell`（2200） |
| Detail | 2280全宽（hero 甚至随 vw 增长） | 挂 `.content-shell`；hero 高度另见 §四 |
| Player | 2542 全宽 | 挂 `.content-shell--narrow`（demo 默认 1920，可调） |
| Settings | 需复核后统一 | — |

### G2. 字号收敛（三选一，demo 内可并排对比）

- **方案 A（推荐）**：`@media (width ≥ 2560px)` 给 `--ui-scale` 一个校准值（建议 **1.08**，一次到位、禁二次跳变——符合 2026-09-04 大屏整合「阶段 D 真机校准」预留）。文字/控件等比 +8%，1440 基线零影响。
  ⚠️ 连带：`--card-size` 会 ×1.08（290→313px），8 列内容区 2200 下仍成立（8×313+7×gap ≈ 2600 > 2200，实际 auto-fill 会落回 6~7 列，需在 demo 里确认观感）。
- **方案 B（保守）**：只放大最小几档字号，间距/控件不动：≥2560 时 `--text-2xs 10.3→11.5 / xs 11→12.5 / sm 12→13.5 / base 13→14.5`。风险：字与控件比例轻微失配。
- **方案 C（只调颜色不动字号）**：维持字号，仅做 G3。适合「其实还能看清，主要是灰字太淡」的判断。

### G3. 边框 / 辨识度（颜色问题，建议全局生效或 ≥2560 生效两档都给）

```css
/* 档 1（推荐）：全局把边框整体提一档——现值本来就近乎不可见 */
:root {
  --color-border: #bfbfbf;        /* 1.57:1 → ≈2.4:1，即原 --color-border-strong 值 */
  --color-border-light: #dcdcdc;  /* 卡片/分组浅边框同步微提 */
  --color-tab-inactive-text: #8c8c8c; /* 2.6:1 → ≈3.5:1 */
}
/* 档 2：只在 ≥2560 覆盖，1440 基线绝对零回归 */
@media (width >= 2560px) { :root { /* 同上三行 */ } }
```

> 何时用档 1：如果 1440 下你也觉得边框浅（对比度数据支持）；何时用档 2：只想修大屏。**需用户拍板。**

## 二、【IPTV 页】

### I1. Tab 组件重构 —— 4 套风格模板（demo 可切换）

现结构：数据源 chips（`.iptv-filter-tag.source-tag`，IPTV.css:241-269）+ 分组 hot-tags（GroupPicker.css:8-35）。两者是「两套长得像但不一样」的胶囊，建议统一为同一个 Tab 模板。demo 提供：

| 模板 | 风格 | 适用 |
|------|------|------|
| T-A 胶囊描边（现风格收敛版） | 白底 + 加深描边 + 选中黑底反白 | 最小改动 |
| T-B 分段控件 Segmented | 灰底轨道 + 白色滑块 + 阴影 | 源切换（≤7 项，强「互斥」语义） |
| T-C 下划线 Tabs | 无底、文字 + 2px 下划线 | 分组（数量多、可换行场景） |
| T-D 卡片式 Tag | 浅灰卡 + 图标 + 计数徽标 | 数据源（信息量大时） |

**尺寸收敛（「type 筛选区域偏大」的修正）**：大屏下 chips 的问题 = 高度档（36px）+ 大间距（space-sm 9px gap、外层 space-md 12.5px padding）+ 12px 字在小屏合理、在大屏相对 2200 宽内容显得「矮胖稀疏」。模板统一后给 ≥2560 一档紧凑变量：

```css
@media (width >= 2560px) {
  .iptv-filter-tag, .grouppicker__hot-tag {
    height: 32px;                 /* 36 → 32 */
    padding: 0 14px;              /* 收敛水平内距 */
    font-size: var(--text-sm);    /* 保持 12px，随 G2 方案联动 */
  }
}
```

### I2. 「全部」按数据源逻辑分组（参考收藏页 `collection-section` 模式）

选中「全部源 + 全部分组」时，网格不再一锅端，改为**按源分节**：每节一个 section 头（源名 + 频道数）+ 该源频道网格。结构照抄 Collections.css:18-35 的 section-head 体系：

```tsx
{/* index.tsx filteredChannels 渲染处，selectedSource===null 时分节 */}
{selectedSource === null ? (
  aggregatorUrls.map((_, i) => {
    const list = displayedChannels.filter(ch => ch.sourceId === `source-${i}`);
    if (!list.length) return null;
    return (
      <section key={i} className="iptv-source-section">
        <div className="iptv-source-section__head">
          <span className="__title">{sourceNames?.[i] || `源 ${i+1}`}</span>
          <span className="__count">{list.length} 个频道</span>
        </div>
        <div className="iptv-channel-grid">{list.map(ch => <IPTVChannelCard key={ch.id} channel={ch} />)}</div>
      </section>
    );
  })
) : ( /* 现状单网格 */ )}
```

### I3. type 筛选区尺寸 → 已并入 I1 模板 + G2。

## 三、【Browse 搜索页】

### B1. Tab 筛选区 UI 重构
现问题：`browse-search-tabs`（描边胶囊组，Browse.css:168-200）与 FilterBar chips（FilterBar.css:132-171）与排序 tabs（Browse.css:126-146）三套视觉并存。重构 = **复用 §二 的统一 Tab 模板**（同模板不同 variant），demo 给出 T-A / T-B / T-C 在 Browse 场景的完整效果。

### B2. 2560+ 尺寸收敛
与 I1 同构：Tab 高度统一 32px 档、图标走 `--icon-sm`（≈15.6px）不用 `--icon-md`、chip 间距 `--space-sm→--space-xs-plus`。FilterBar 的 label-as-chip（FilterBar.css:40-52）同步收敛。

## 四、【Detail 详情页】顶部图片过高 —— 3 套布局方案

**根因**：hero `aspect-ratio: 16/9` + `max-height: min(65vh, var(--layout-detail-hero-max-h))`（Detail.css:24-33）；而 `--layout-detail-hero-max-h` 在 ≥1920 走 `42.4vw` 曲线（variables.css:864）→ 2560×1440 下 = min(936px, 1085px) = **936px，占屏高 65%**。

| 方案 | 思路 | 关键代码 |
|------|------|----------|
| D-A 高度封顶（改动最小） | ≥2560 时 hero 上限从 65vh 降到 52vh，并把 ≥1920 的 42.4vw 曲线封顶 | `@media (width>=2560px){ .detail-hero{ aspect-ratio:auto; max-height:min(52vh,700px);} }` |
| D-B 横向分栏 | hero 固定 480px 高；左侧信息（标题/meta/按钮）移出图片、落在右侧海报旁的纯色区 | 见 demo D-B（grid 两列：图 60% + 信息 40%） |
| D-C 紧凑条幅 + 悬浮海报 | hero 压到 21:9（≈340px）做背景条；海报负 margin 悬浮跨越 hero 与内容区（豆瓣/YouTube 风） | 见 demo D-C |

## 五、【Play 播放页】播放器占 2/3 屏 —— 3 套布局方案

**根因**：`.player-page{min-height:100dvh}` + `.player-main{height:100%}` + `.player-video-area{flex:1;height:100%}`（Player.css:1-27）→ 视频区 = 全宽（2542px）× 全高（1422px），侧栏固定 320px（Player.css:70-77）。

| 方案 | 思路 | 关键代码 |
|------|------|----------|
| P-A 内容封顶 + 16:9 限高（推荐先做） | `.player-main` 挂 `content-shell--narrow`（1920）；video-area 改 `aspect-ratio:16/9; height:auto; max-height:calc(100dvh - 32px)` | demo P-A |
| P-B 双列剧场 | 视频限高后，剩余竖向空间给右侧信息/选集面板加高 + 底部横排「继续观看」 | demo P-B |
| P-C 用户可切「适配/填充」 | 保留现状满高为「填充」档，新增「适配」档，设置记忆 | 逻辑改动，demo 只示意 |

## 六、【Person 页】纯色背景块过大 —— 3 套方案（含示例代码）

**根因**：`.person-hero` min 448 / max `min(50vh, 640px)`（Person.css:23-34）→ 2560×1440 下 640px 高的近纯黑块（背景 `rgba(0,0,0,0.92)`），信息密度极低。

| 方案 | 思路 |
|------|------|
| PS-A 压缩高度 | min 320 / max `min(40vh, 460px)`；字号/头像 clamp 上限同步降 |
| PS-B 横幅 + 悬浮头像卡 | hero 280px 条幅；头像卡负 margin 下沉，信息区落回浅色内容区（demo 附完整代码） |
| PS-C 背景图片化 | 纯色换人物背景图 + 深色渐变遮罩（Detail hero 同款双层渐变），高度不动但视觉有内容 |

## 七、实施顺序建议（拍板后）

1. **G1 内容壳 + G3 边框**（低风险、全端收益）→ 2. **I1/B1 Tab 模板**（demo 选型）→ 3. **I2 全部按源分组** → 4. **Detail/Play/Person 布局选型** → 5. **G2 字号方案**（最后做，需真机重感）。

> 红线自查：不动 `--layout-content-max-width` 的 2200；所有新 `@media ≥2560` 尺寸规则加 `html:not([data-device="tv"])` 前缀（TV 走独立 2× 曲线）；1440 基线零回归。
