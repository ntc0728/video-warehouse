背景色对比度整改 · 方案总览

问题：页面底与卡片扫光/等待占位/失败占位几乎同色，状态糊成一片。以下三个方案 demo 各自内含 OLD↔NEW 并排对比 + 亮/暗主题切换。

问题量化（现状，均为同色相中性灰、只差一丝明度）

页面底 #f5f5f5
扫光起 #ececec → 1.08:1
扫光止 #dcdcdc → 1.26:1
等待/失败底 #e9e9e9 → 1.11:1
tag/收藏/分页底 #f5f5f5 → 1.00:1（完全同值）
暗色主题同病：页面底 #141414 vs 占位 #262626（1.22:1）/ 扫光止 #333（1.46:1）。WCAG 对有意义视觉元素建议 ≥3:1；行业骨架类实践普遍 1.3~1.6:1 且依赖色相/高光带增强可辨性。

方案 A · 中性灰阶拉开 + 独立高光带

改动最小 · 调性最稳

占位整体压深一档（1.33:1），扫光改为「静止底 + 白色高光带掠过」（Facebook/AntD 同款机制），扫光可见性不再受底色上限约束。

适合：想保持现有极简灰调、风险最低

方案 B · 冷调蓝灰占位（色相差异化）

hue 解耦 · 一眼可辨

页面底不动，占位色族带低饱和蓝相（Facebook #e4e6eb / B站 / Tailwind slate 主流做法）。人眼对色相差远比对同色相 ΔL 敏感。

适合：接受占位带一点冷色、追求现代社交站质感

方案 C · 媒体面恒深（主题解耦）

影院感最强 · 变化最大

封面占位两主题统一用固定深底（Disney+/Prime/YouTube 浅色主题下海报占位仍是深色）。与任何页面底天然大对比，是项目「媒体上下文族」契约的延伸。

适合：想要流媒体影院质感、浅色主题一步到位解决
三方案均只动 token 层（variables.css 色源 + 少量新 token），消费方（LazyImage / Skeleton.css / 各页骨架 / VideoCard 封面底）经 var() 自动生效。 通用附带项：--color-tag-bg / --color-favorite-bg / --color-page-btn-bg 浅色档与页面底 #f5f5f5 同值，任一方案落地时建议一并提档至 #e8e8e8。
