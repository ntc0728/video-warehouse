V4 相对 V3 的三处结构调整（均针对你提出的三个问题）

问题V4 结构理由 / 代码成本
tabs 放侧栏内是否好？ 通栏：模式行独占一行，与内容区左右对齐 智能检索/直链搜索是页面级模式切换，塞 264px 窄列视觉与语义双降级；通栏后 results 不再跨行，V3 发现的 grid 行高分配 Bug 天然消失（连 grid-template-rows 修复都不再必需，仍建议保留防御）。成本：BR-C 块 areas 改 'tabs tabs' / 'side results'，纯 CSS
直链搜索下面板消失、左列空洞 直链搜索整体退单列：无侧栏，CMS 卡片全宽（minmax 300px） 直链搜索本就无筛选维度（CMS 全量搜索），左列空 264px 纯浪费。成本：TSX 根节点按 searchMode 加 browse-page--cms 类（一行）+ CSS 一条 grid-template-columns: 1fr 分支
「类型」为何在面板内？ 推荐：类型出面板，与排序同行置于结果区头部（[全部|电影|剧集] | [排序 tabs] [共 N 条]）；备选：留面板顶部但升级为分段控件 + 分隔线分层 类型决定 discover 查 movie/tv 与 genres 集合，是顶层维度，与分类/地区/评分平级是层级错误；且直链搜索无类型维度——类型随智能检索区走，切直链时自然消失，无层级矛盾。成本：FilterBar 加 hideType prop，Browse 桌面自渲染类型分段（中等）

实施清单（确认后落地）

① Browse.css BR-C 块：areas 改通栏 + 保留 grid-template-rows: auto minmax(0,1fr) 防御 + cms 单列分支；② Browse/index.tsx：根节点按 searchMode 加类；③ FilterBar：加 hideType prop（默认 false，历史页等调用方零回归），Browse 桌面端渲染类型分段进结果区头部；④ build + E2E。
