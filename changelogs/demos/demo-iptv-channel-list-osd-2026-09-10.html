1议题一 · 频道列表「一级 / 二级」宽度

现在是硬 50%/50%（.up-channel-groups 与 .up-channel-channels 的 width / max-width 都写 50%）。 但两级的内容性质完全不同：一级是 10 条写死的分类文本（全部频道 / 央视 CCTV / 主流卫视 …）， 最长一条「央视 CCTV」在任何视口下只需要 61–66px，算上计数药丸与内边距， 需要宽度全程只有 109.8–116.5px（见下方分配表末行），与视口宽度没有强相关； 二级是自由频道名（「CCTV-5 体育赛事高清频道」实测 249px），宽度需求无上限。 50/50 等于把一半宽度让给了有上限的一侧 —— 实测 1440 下一级空转 97px（44%，占比 222.3 中的 97）， 同时二级连「CCTV-1 综合」以外的名字都挤到了边界：1440 下频道名只剩 122.2px， 而最长名 157px 已经 截断 34.9px。

各方案的实际分配（一级 / 二级，单位 px；每格下方标注一级空转 / 截断量）

方案 A 的选取依据：一级栏的最小可用宽度 = 行左内边距 + 最长分类名 + 与计数药丸的间距 + 药丸宽 + 行右内边距。 10 条分类是常量，逐档实测这个值只有 109.8 / 114.0 / 113.7 / 113.5 / 113.3 / 116.5px （480 / 768 / 1024 / 1280 / 1440 / 1920；375 走窄屏样式 = 99.5px）—— 行内边距随档变大、字号在 768 后反而变小，两者相抵后近乎恒定，与视口宽度没有强相关。 所以取内容派生的定值 132px（= 116.5 + 13% 余量；余量给足是因为中文字体回退 会让「央视 CCTV」这类「中文 + 拉丁数字」混排的宽度实测漂 3–5%）， 而不是视口派生的比例 —— 比例档在窄屏会崩（见方案 B）。

窄屏（≤479）单独一档：280px 的面板上 132px 会占到 47%，与 50/50 相差无几， 所以在这一档把组项字号降到 --text-sm、行内边距降到 --space-sm， 需要宽度随之降到 99.5px → 一级栏取 116px（占面板 41.4%），剩下的 164px 全给二级； 再把质量徽章隐藏，375 下频道名可用宽度从现状的 54.5px 提升到 140px（+157%）。 断点处（479→480）一级栏 116→132px 有一次 16px 的跳变 —— 与面板宽度本身的档位跳变同步，可接受。

口径提醒：分类的活跃态是 font-weight:600，而最长的「央视 CCTV」随时可能成为活跃项， 所以设计宽度必须按 600 字重的自然宽度算。用渲染宽度算会自证「刚好放得下」 （.up-channel-group-text 带 text-overflow:ellipsis，栏窄时渲染宽被裁到可用宽）。 本 Demo 面板与分配表共用同一个量测函数，两处读数必然一致。

方案 C 只对 ≥768 有效：--layout-episode-panel-w 的下限是 420px， 375 视口下会超出屏幕。而且它治标不治本 —— 一级空转从 44% 涨到 53%。

/* variables.css —— 新增 token（放在 --layout-panel-medium-w 附近）

方案 B（clamp(96px, 32%, 148px)）作为「不想引入新 token 语义」的保守替代： 1440 下一级 142.3px（比 A 多 10.3px 空转），768 及以上都不截断， 但 375 下只有 96px、分类名被截断 22.6px —— 比例档在极窄屏必然崩， 要么接受截断、要么再补一条窄屏例外（那就等于又回到 A 的复杂度，却少了内容派生的依据）。 切到「压力（超长名）」可看到：常规站名 A 全程不截断；249px 的极端名没有任何 固定栏宽能容下，只能靠二级吃满剩余宽度 + 继续走 marquee —— 这正是 A 的设计前提。

2议题二 · OSD 栏宽度合理性

--layout-osd-max-width 是「以 1080p 为锚点」的两段式 clamp（<1024 一段、≥1024 一段， 1440 落点 1208.94px）。问题是：这条曲线在 约 420–1158px 视口区间恒大于「视口 − 2×--space-md」， 于是被 max-width 兜底规则截断 —— 这一段 OSD 实际是贴边的，宽度 token 完全不起作用。 表现为「视口越窄、OSD 占比越高」这条反直觉的曲线：1024 时占 98.0%（左右各只剩 10px），768 时占 99.1%， 而 1920 反而只有 69.9%。

可用宽度上限 100% − 2×--space-md 现状 --layout-osd-max-width（红字 = 被 max-width 吃掉） 建议 clamp(320px, 78vw, 1400px)

建议曲线 clamp(320px, 78vw, 1400px) 的取值

  • 375 → 320px（85.3%，与现状一致）：小屏本来就需要尽量宽；这条曲线在 410px 以下仍由下限托住。
  • 768 → 599px（78.0%，现状 97.5% 贴边）、1024 → 798.7px（78.0%，现状 98.0% 贴边）： 这两档收益最大 —— 左右各留出 84–113px，OSD 不再像被拉满的横条。
  • 1440 → 1123.2px（78.0%，现状 84.0%）：基本持平，曲线在 1795px 触顶 1400 后冻结 （与 --layout-content-cap 的 2200 封顶哲学同源）。
  • 1920 → 实测 1413.4px（73.6%）：不是 1400 —— 差值是 --ui-scale 带来的。 该 token 整体乘了 --ui-scale，而 ≥1920 的曲线 0.76 + 0.000125 × 视口宽 在压缩后系数变成 0.00013， 1920 处得 1.0096 → 1400 × 1.0096 = 1413.4；2560 处 --ui-scale 取上限 1.08 → 1512（59.1%）。 这是既有行为（旧的 1080p 锚点曲线同样被乘），非本次引入。本页图表为了让曲线可比，未叠加 --ui-scale。
  • 单调、无截断段：一条比例曲线 + 上下限，不再出现「中间某段 token 失效」。
  • TV 档不动：.up-platform-tv 的 clamp(1600px, 83.333vw, 3200px) 是独立的 2× 契约，保留。
/* variables.css —— 删掉 <1024 与 ≥1024 两段锚点曲线，合并为一条比例曲线 */
--layout-osd-max-width: calc(clamp(320px, 78vw, 1400px) * var(--ui-scale));

/* IPTVOSDBar.css —— 边缘留白随档位放大（原为固定 --space-md） */
.iptv-osd-bar {
  max-width: calc(100% - 2 * var(--space-lg));
}

3议题三 · OSD 栏内部布局

当前是「左翼固定宽 + 中列吃剩余 + 右翼最小宽」的三段 flex。因为 左翼（--layout-channel-num-w 120→180px）恒大于右翼（--layout-quality-badge-min-w 84→120px）， 中列的中心并不等于 OSD 的中心 —— 1440 实测左翼 169.4 / 右翼 113.6，相差 55.8px， 于是位于中列的控件行整体右偏 27.9px（OSD 中心 719.95，控件中心 747.85）。 下面的对比里，三个 bar 都是真的 DOM，读数取实时 getBoundingClientRect。

取舍项 v2 = v1 + 频道号与台名同排 —— 本次未采纳

v2 把「频道号」从独占一行并到台名同行（左翼高度 53.7px → ~27px，三栏垂直重心更齐）。 但它是有代价的取舍，不是纯改善：号进入同一行后会吃掉 ~27px， 台名可用宽度从 134.8px 降到 ~104px，「CCTV-5 体育赛事高清」这类长台名会更早开始跑马灯。 现状左翼 53.7px 高与中列 66.7px 本就不齐，但三栏都垂直居中，观感问题不大 —— 所以 这一项建议由你裁决：要「更紧凑的垂直节奏」还是「更长的台名可见宽度」。

4顺带发现 · 频道列表活跃态在播放器里不可见

排查宽度时实测到的既有缺陷，不在本次诉求内，一并留痕：播放器页面跑在应用默认的浅色主题下， --color-primary 在浅色主题是 #000；而频道列表面板本身是 rgba(0,0,0,.60) 压在视频黑场上 —— 于是所有「用 primary 做强调」的规则全部退化成黑色。

规则实际算出的值实际效果
.up-channel-group-active::before（一级活跃左竖条）rgb(0, 0, 0)完全不可见（1.84 × 16.5px 的黑条压在黑面板上）
.up-channel-item-active（二级活跃左边框）3px rgb(0, 0, 0)完全不可见
.up-channel-group-active .up-channel-group-countcolor(srgb 0 0 0 / 0.12)比未选中态的 rgba(255,255,255,.06) 更暗 —— 选中反而更弱
.up-channel-item-active .up-channel-item-numcolor(srgb 0 0 0 / 0.65)不可见（序号本该高亮）
目前唯一生效的活跃线索rgba(255,255,255,.12) 行底色 + 字重加粗（见 §1 面板截图里「央视 CCTV」那行）
