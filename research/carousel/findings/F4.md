# F4: Bundle size and performance comparison

## Findings

### [1] Embla Carousel React v8.6.0 is the smallest: 7.3KB gzipped (18KB minified), zero CSS required
- quote: "A lightweight carousel library with fluid motion and great swipe precision" — bundlephobia: gzip 7,277 bytes, min 17,975 bytes, 0 direct JS dependencies, 2 transitive (reactive-utils 1.5KB + core 33KB on disk)
- url: https://bundlephobia.com/api/size?package=embla-carousel-react@8.6.0
- source_type: primary (bundlephobia automated build)
- published: 2025 (v8.6.0)
- confidence: high

### [2] Swiper v14.0.5 JS core is 19.6KB gzipped (65KB minified) — roughly 2.7x Embla's size
- quote: "gzip": 19575, "size": 65295, dependencyCount: 0
- url: https://bundlephobia.com/api/size?package=swiper@14.0.5
- source_type: primary (bundlephobia automated build)
- published: 2026-07-10 (v14.0.5)
- confidence: high

### [3] react-slick v0.30.0 is 15.7KB gzipped (62KB minified) with 6 transitive dependencies including resize-observer-polyfill and lodash.debounce
- quote: "gzip": 15734, "size": 61630, dependencyCount: 6 — includes resize-observer-polyfill (7.4KB), enquire.js (2.2KB), lodash.debounce (1.6KB)
- url: https://bundlephobia.com/api/size?package=react-slick@0.30.0
- source_type: primary (bundlephobia automated build)
- published: 2024 (v0.30.0)
- confidence: high

### [4] react-responsive-carousel v3.2.23 is 9.3KB gzipped (37KB minified) — second smallest JS
- quote: "gzip": 9299, "size": 36843, dependencyCount: 3 — includes react-easy-swipe (5.7KB), classnames, prop-types
- url: https://bundlephobia.com/api/size?package=react-responsive-carousel@3.2.23
- source_type: primary (bundlephobia automated build)
- published: 2023 (v3.2.23)
- confidence: high

### [5] Swiper requires mandatory CSS imports adding ~8-12KB gzipped; Embla and react-slick need no CSS at all
- quote: Swiper official docs: "Import Swiper styles: import 'swiper/css'" — core CSS is required; navigation/pagination add additional CSS files. `swiper/css/bundle` (all modules) adds roughly 8-12KB gzipped.
- url: https://swiperjs.com/react
- source_type: primary (official docs)
- published: 2026
- confidence: medium (CSS size not from bundlephobia; estimated from Swiper's ~132KB package footprint minus the 65KB JS)

### [6] Swiper's total realistic footprint (JS + CSS core + nav + pagination) is ~28-30KB gzipped vs Embla's 7.3KB — a 4x difference
- quote: Swiper comparison page: "Bundle Size (gzipped): ~25-45KB (modular)" for Swiper vs "~3-5KB core" for Embla
- url: https://swiperjs.com/compare/swiper-vs-embla-carousel
- source_type: primary (official comparison)
- published: 2026
- confidence: medium (official claim, not independently verified)

### [7] react-slick has 6 dependencies including a resize-observer-polyfill (7.4KB), inflating its real cost well beyond the headline 15.7KB
- quote: dependencySizes includes resize-observer-polyfill (7,411 bytes), enquire.js (2,175), lodash.debounce (1,573), classnames (700), json2mq (428), string-convert (108)
- url: https://bundlephobia.com/api/size?package=react-slick@0.30.0
- source_type: primary (bundlephobia automated build)
- published: 2024
- confidence: high

### [8] Embla's headless architecture means zero runtime UI overhead — no DOM creation for arrows/dots/pagination unless the developer adds them
- quote: Swiper comparison: "Embla Carousel is intentionally headless. It provides the carousel engine — the scroll physics, snap points, and slide management — but no UI components at all."
- url: https://swiperjs.com/compare/swiper-vs-embla-carousel
- source_type: primary (official comparison)
- published: 2026
- confidence: high

### [9] Swiper has sideEffects: true (bundlephobia), meaning Vite/esbuild cannot tree-shake unused modules without explicit side-effect-free CSS imports
- quote: `"hasSideEffects": true` — Swiper v14.0.5; Embla v8.6.0 has `"hasSideEffects": false`
- url: https://bundlephobia.com/api/size?package=swiper@14.0.5
- source_type: primary (bundlephobia automated build)
- published: 2026
- confidence: high

### [10] Embla Carousel autoplay plugin adds only 1.1KB gzipped — modular cost is minimal
- quote: embla-carousel-autoplay@8.6.0: gzip 1,064 bytes, min 2,344 bytes, 0 dependencies
- url: https://bundlephobia.com/api/size?package=embla-carousel-autoplay@8.6.0
- source_type: primary (bundlephobia automated build)
- published: 2025
- confidence: high

## Dead ends
- Bundlephobia CSS data is not available via API — only JS assets are returned; Swiper CSS sizes had to be estimated from package footprint and Swiper's own comparison claims.
- GitHub README fetch for embla-carousel timed out; used Swiper's official comparison page instead.
- No independent runtime performance benchmarks (render time, memory usage, FPS during transitions) were found for these four libraries — only bundle size data is reliably available from primary sources.

## Suggested follow-ups
- Run an actual Vite production build with each library imported to measure real output size after tree-shaking and CSS extraction.
- Benchmark slide transition frame rates and memory usage using Chrome DevTools Performance panel with 50+ slides.
- Check if Swiper's `sideEffects` flag can be overridden in vite.config.ts to improve tree-shaking.
