# KinoTV 生产级对标调研报告（2026-08-05）

> 调研方法：① 逐页代码级盘点（11 个页面 + 核心组件）；② 联网调研生产级影视应用功能标准（Netflix 类 20 大必备功能 Oyelabs 2024-10、HTML5 播放器控制标准、国内流媒体对比）。
> 定位：KinoTV 是**单用户本地影视聚合应用**（无账号体系，数据存 IndexedDB/localStorage），对标对象是「生产级影视应用」的功能完整性，但**账号/多用户/订阅等商业能力按定位排除**。

---

## 一、总体结论

KinoTV 在**前端工程化与多端交互**上已达较高水准（三端适配、Keep-Alive、骨架屏/懒加载、深链、键盘/TV 遥控、错误/空态反馈齐全），核心链路「发现→详情→选源→播放→历史→收藏→续播」闭环良好。

对照生产级标准，主要短板集中在**产品层功能**（播放器占位空实现、首页续播入口弱、状态持久化缺失、无个性化）与**少数真实缺陷**（空回调按钮、缓存过期无强制刷新）。

| 维度 | 评级 |
|------|------|
| 页面交互完整性 | ★★★★☆（11 页交互齐全，细节扎实） |
| 播放器控制 | ★★★☆☆（点播控制极全，**IPTV OSD 有空回调**） |
| 数据持久化 | ★★★☆☆（本地完善，无云同步、筛选状态不落 URL） |
| 个性化/推荐 | ★★☆☆☆（无基于历史的推荐、无"猜你喜欢"） |
| 国际化 | ★★☆☆☆（全中文硬编码，无 i18n） |

### 2.2 HTML5 播放器控制标准（业界标配）

播放/暂停、进度条（含缓冲）、音量、**倍速**、**画中画**、**清晰度切换**、**音轨切换**、字幕为**标配控制**。

→ KinoTV 点播模式：以上全部具备（含截图/解码切换/循环/镜像/比例，超配）。
→ **IPTV 模式：设置/清晰度/音轨按钮存在但回调为空**（实锤，见 H-2）。

## 三、真实缺陷（已代码验证，建议优先修复）

### H-1【高】首页缺「继续观看/最近观看」聚合区块
- **证据**：`Home/index.tsx:125` 注释明示「继续播放」仅在 HeroBanner 单条 CTA；无独立「继续观看」行。
- **生产级依据**：Netflix 首页首屏必有「Continue Watching」横排（第 14/18 功能）。
- **影响**：大量有进度的影片只能靠 Banner 一条续播，用户续播路径冗长。
- **建议**：在 HeroBanner 下方、分类快选上方插入「继续观看」横排（读 useUserStore 历史按 updatedAt 排序取最新，点击直达 /play）。

### H-2【高】IPTV 播放器 OSD「设置/清晰度」按钮空回调（用户点击无反应）
- **证据**：`UniversalPlayer.tsx:668-671` 传 `onOpenSettings={() => {}}` / `onOpenResolution={() => {}}` / `onHeightChange={() => {}}`。
- **生产级依据**：HTML5 播放器控制标准中清晰度/设置为标配。
- **影响**：IPTV 直播中用户点「设置」「清晰度」按钮无任何反馈，属功能性缺陷。
- **建议**：
  - 清晰度：直播流通常单清晰度，**隐藏按钮**（比空回调诚实）或实现软解码器选择弹层。
  - 设置：实现简易设置面板（音量/缩放/解码模式），或隐藏。
  - 音轨：`handleAudioTrackSelect` 已在，但 OSD 渲染需 `audioTracks.length > 1`，确认直播场景该值是否有值；无值时应隐藏音轨按钮。

### H-3【中】Browse 筛选/排序状态不持久化到 URL
- **证据**：`src/pages/Browse/` 全目录无 `URLSearchParams`/`location.search` 读写。
- **生产级依据**：主流影视站（IMDb/豆瓣）筛选排序均入 URL 可分享/刷新保持。
- **影响**：用户设置筛选后刷新/分享链接即丢失，深链只能带 q/category。
- **建议**：将筛选/排序/模式编码进 URL query（如 `?q=&category=&genre=&sort=`），初始化读取、变更回写（replaceState 防历史堆积）。

### H-4【中】History 删除粒度过粗（按 videoId 整剧删除）
- **证据**：删除按 videoId（含多季多集）。
- **生产级依据**：主流应用历史删除支持「删单集/删整剧」两级。
- **建议**：删除确认弹窗提供「删除该集/删除整剧」两个操作（需 History 记录细分到 episode）。

### H-5【中】无基于本地历史的个性化推荐
- **证据**：首页 7 行全 TMDB 通用行，无基于收藏/历史的"猜你喜欢"。
- **生产级依据**：Netflix 第 6/19 功能（基于行为推荐）。
- **建议**：首页加「为你推荐」行（按收藏/历史影片的 genre_ids 聚合，从 TMDB discover 拉同类型）。

### H-6【低】收藏缺「评分/标记已看/分组」
- **证据**：Collections 仅二态收藏 + 状态筛选，无用户评分与自定义分组。
- **生产级依据**：Netflix 第 9 功能（用户评分/评论）。
- **建议**：收藏卡片加评分（1-5 星）与「标记已看」快捷操作。

### H-7【低】SourceChecker 缓存过期无强制刷新区分
- **证据**：30min 缓存 + isCacheExpired 标黄，但点检测仍按 tab 手动。
- **建议**：结果区加「立即重测」按钮强制绕过缓存。

### H-8【低】多语言 i18n
- **证据**：全中文硬编码文案 + TMDB 语言手动切换。
- **生产级依据**：Netflix 第 13 功能。
- **建议**：引入轻量 i18n（如 i18next），文案抽离。工程量中等，按需决定。

## 四、交互合理性（盘点发现，均合理或有明确取舍）

| 页面 | 结论 |
|------|------|
| Home | 移动端隐藏缩略图列合理；但 Banner 无指示点/箭头，轮播为隐式（低优改进） |
| Browse | 移动端排序收进抽屉合理；直链模式无排序/筛选是代码注释明确的取舍（低优） |
| Detail | 演员点击跳人物页合理；剧照仅 backdrops（低优） |
| Player | 点播控制超配；IPTV 空回调是唯一缺陷（H-2） |
| Settings | 个人资料/备份/恢复齐全；缺字幕样式/默认清晰度偏好（低优） |
| Collections | 状态筛选/批量管理/排序齐全；缺评分/分组（H-6） |
| History | 时间轴/分组/批量齐全；删除粒度粗（H-4） |
| SourceChecker | 5 维检测/缓存/统计齐全；缺强制刷新（H-7） |
| Person | Hero/Tab/懒加载齐全；简介折叠无阅读进度记忆（低优） |
